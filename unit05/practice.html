练习 1 · 给待办清单加排序 ​

在案例 01 的基础上做两个扩展。

扩展一：按优先级排序。

优先级有高、中、低三档。要求：

项目要求
排序选项一个下拉框：默认顺序 / 优先级从高到低 / 优先级从低到高
排序实现用计算属性，不要用 watch
依赖关系排序发生在筛选之后（先筛出要显示的，再排序）

扩展二：按截止时间排序。

要求同上，另加两条：

  • 没有截止日期的任务，无论升序降序都排在最后；
  • 截止时间相同的任务，保持原顺序（不要出现“每次排序结果都不一样”）。

提交形式：完整的 TaskListView.vue，外加一份 100 字的说明， 画出你的派生链（哪些是源头、哪些是算出来的）。

验收标准

项目要求
派生链排序是计算属性，全程没有新增 watch
排序正确性三档优先级的顺序正确；无截止日期的排最后
稳定性同优先级的任务相对顺序不变
组合正确排序和筛选能同时生效
参考思路

优先级排序要先做一次“文本到数字”的映射：

js
const PRIORITY_RANK = { high: 0, medium: 1, low: 2 }

const sortedTasks = computed(() => {
  const list = filteredTasks.value
  if (sortBy.value === 'priority-desc') {
    return list.toSorted((a, b) => PRIORITY_RANK[a.priority] - PRIORITY_RANK[b.priority])
  }
  if (sortBy.value === 'priority-asc') {
    return list.toSorted((a, b) => PRIORITY_RANK[b.priority] - PRIORITY_RANK[a.priority])
  }
  return list
})

“无截止日期排最后” 的写法：把没有日期的当成一个极大值。 但注意升序和降序要分开处理 —— 降序时极大值会跑到最前面， 所以不能简单地“给个极大值”，要在比较函数里显式判断：

js
function compareByDeadline(a, b, dir) {
  // 空值永远排最后，与方向无关
  if (!a.deadline && !b.deadline) return 0
  if (!a.deadline) return 1
  if (!b.deadline) return -1
  return a.deadline.localeCompare(b.deadline) * dir
}

“保持原顺序”：Array.prototype.sort 在现代浏览器里是稳定的， 所以同值时天然保持相对顺序。这也是为什么不能用随机数做 key —— 排序的稳定性依赖“原始顺序”这个隐式信息。

功能说明

项目要求

练习 4 · 表单草稿自动保存 ​

用 watch 实现一个“表单自动保存草稿到 localStorage”。

需求

  1. 表单有三个字段：活动标题、名额、报名截止时间；
  2. 任意字段变化后 1 秒内保存一次草稿（防抖）；
  3. 页面打开时自动读取草稿并填充，同时提示“已恢复上次的草稿”；
  4. 点击“提交”后清空草稿；
  5. 提供“清除草稿”按钮，点击后清空表单和存储。

技术要求

项目要求
防抖用 setTimeout + onCleanup 清理，不要留下未清理的定时器
清理组件卸载时不能有未执行的定时器
容错localStorage 里存的可能是损坏的 JSON，读取时要 try / catch
空值三个字段都为空时不要保存草稿（避免存一个空对象）
参考思路
js
import { reactive, watch, onMounted } from 'vue'

const DRAFT_KEY = 'activity-form-draft'
const form = reactive({ title: '', capacity: '', deadline: '' })
const restored = ref(false)

watch(
  () => ({ ...form }),
  (snapshot, _old, onCleanup) => {
    const timer = setTimeout(() => {
      // 全空就不保存，顺便清掉旧草稿
      const isEmpty = !snapshot.title && !snapshot.capacity && !snapshot.deadline
      if (isEmpty) {
        localStorage.removeItem(DRAFT_KEY)
        return
      }
      localStorage.setItem(DRAFT_KEY, JSON.stringify(snapshot))
    }, 1000)

    onCleanup(() => clearTimeout(timer))
  }
)

onMounted(() => {
  const raw = localStorage.getItem(DRAFT_KEY)
  if (!raw) return
  try {
    Object.assign(form, JSON.parse(raw))
    restored.value = true
  } catch {
    localStorage.removeItem(DRAFT_KEY)   // 损坏的数据直接清掉
  }
})

function submit() {
  // 提交逻辑
  localStorage.removeItem(DRAFT_KEY)
  restored.value = false
}

三个关键点：

  1. 用 () => ({ ...form }) 作为来源。 这样每次变化后回调拿到的是一个 快照（新对象），不会被后续修改影响 —— 正好避开对象新旧值相同的坑；
  2. Object.assign(form, parsed) 而不是 form = parsed。form 是 reactive 对象，整体替换会丢响应性；
  3. try / catch 不能省。 用户可能手动改过 localStorage， 里面存的东西不一定是合法 JSON。

验收标准

项目要求
防抖有效连续输入时只在停下来 1 秒后写入一次
卸载干净输入后立刻切走页面，控制台无报错
容错手动把存储值改成乱码，页面能正常打开且清掉脏数据
空值不存清空所有字段后，localStorage 里没有草稿
一个可以顺手做的优化

加上“草稿保存中 / 已保存”的状态提示，让用户知道数据是安全的。

js
const saveState = ref('idle')   // idle / saving / saved

在 setTimeout 执行前设成 saving，写入成功后设成 saved， 两秒后回到 idle。这类“让用户安心”的反馈，在真实产品里很重要。

常见问题 ​

排序后取消，顺序没有回到最初，怎么办

这是正常的。toSorted 返回的是“按比较函数排出来的结果”， 取消排序时如果只是不排序，顺序就是上一次筛选/排序后的顺序， 不是最初的原始顺序。

两种处理：

  1. 接受它。 大多数产品就是这样，取消排序表示“按数据源的顺序”。 只要数据源顺序稳定，看到的就是稳定结果；
  2. 要严格恢复原顺序，就得记录原始顺序：
js
const sourceOrder = new Map(activities.value.map((a, i) => [a.id, i]))

// 取消排序时
return filteredList.value.toSorted(
  (a, b) => sourceOrder.get(a.id) - sourceOrder.get(b.id)
)

注意第 2 种做法的代价：sourceOrder 必须在数据变化时同步更新， 又多了一份需要维护的状态。除非产品明确要求，否则选第 1 种。

分页和筛选能不能放在同一个组件里

可以，但组件会长到两三百行。建议按这个顺序拆：

  1. 逻辑抽成组合式函数（useTableQuery），组件只负责渲染；
  2. 分页控件抽成子组件（Pagination.vue），接受页码数据和几个事件；
  3. 表格行抽成子组件，接受一行数据。

拆分时机：当模板里出现了“两个不相关的小节”时再拆。 过早拆分会让你在多个文件之间来回跳，反而更慢。 组件拆分的判断依据见单元 7。

本地筛选需要防抖吗

不需要。 12 条数据的 filter 耗时在微秒级， 加防抖只会让输入显得卡顿（用户打字后要等一下界面才变）。

什么时候需要防抖：

  • 筛选或搜索要发接口请求；
  • 数据量很大（上万条）且要做复杂运算（比如全文匹配）；
  • 筛选会触发很重的渲染（比如上千行的表格）。

判断方法：用浏览器性能面板录一段，看输入时的耗时。 不要凭感觉加防抖，防抖本身也是一种延迟。

练习 2 一定要做 12 条数据吗

是。少于 10 条就翻不了页，分页逻辑的边界情况（最后一页只有 1 条、 总数正好是每页条数的整数倍）就测不到。

这几个边界情况最值得测：

情况要验证什么
总数 12、每页 5最后一页只有 2 条
总数 10、每页 5最后一页正好 5 条，总页数 = 2 而不是 3
总数 0总页数应该是 1，不能是 0（否则页码区域是空的）
筛选后只剩 1 条页码夹回 1，表格正常显示

Math.ceil(0 / 5) 等于 0 —— 这就是为什么代码里要写 Math.max(1, Math.ceil(...))。
