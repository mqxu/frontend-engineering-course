# 单元 10 课后练习

本单元的练习都是"能直接进项目"的产出。**三道必做题，一道选做题。**

必做题做完，你的项目会多出两个新目录：`src/stores/` 里的两个状态模块、
`src/api/` 里的请求层。这三道题合起来正好是第 10 周阶段性任务的全部内容 ——
**把路由与状态接起来，跑通完整的鉴权链路**。

各小节末尾还有针对性的小练习，那些帮助理解单点；这一页的练习是单元级的产出，
作为过程性考核的依据。

## 必做题

### 练习 1 · 活动列表状态模块

按 [10.2 的实战](/unit10/02-pinia-basics#实战活动列表的状态模块)，
写出 `src/stores/activity.js`，并加上持久化。

**要求**

| 项目 | 要求 |
| --- | --- |
| 筛选条件 | 关键词、状态、分页（页码 + 每页条数）都在 store 里，不放组件 |
| 派生值 | 至少两个：是否空数据、总页数 |
| 持久化 | 筛选条件与每页条数持久化，**页码不持久化** |
| 刷新行为 | 刷新页面后，关键词与状态还在，页码回到第一页 |
| 动作 | 取列表、改筛选条件（自动回第一页）、重置筛选 |

**提交形式**：`src/stores/activity.js` 与改造后的 `ActivityListView.vue`。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 数据位置 | 组件里搜不到 `ref` 定义的筛选字段，它们都在 store 里 |
| 持久化字段 | `localStorage` 里只有筛选条件相关字段，没有 `loading`、`error` |
| 响应性 | 组件用 `storeToRefs` 解构状态，改筛选条件页面立刻响应 |
| 刷新验证 | 手动验证：筛出"报名中" → 刷新 → 仍然是"报名中"、第一页 |

::: warning 常见的两种不合格
1. **页码也持久化了**。用户从第一页切到第五页，刷新后停在第五页，
   但数据可能已经变了，这一页是空的 —— 用户会以为"活动都没了"。
2. **直接解构丢响应性**。`const { filters } = useActivityStore()`，
   改筛选条件页面不更新，要手动刷新才看到。
:::

### 练习 2 · 请求层封装

按 [10.4](/unit10/04-request-layer) 写出完整的请求层。

**要求**

| 文件 | 内容 |
| --- | --- |
| `src/api/request.js` | axios 实例（基础地址从环境变量读 + 超时）、请求拦截器注入 token、响应拦截器剥数据判业务码 |
| `src/api/auth.js` | 登录、退出、取当前用户 |
| `src/api/activity.js` | 活动列表、详情、新建、编辑、删除 |
| `src/api/signup.js` | 报名列表、通过、拒绝（带理由） |

**401 处理的具体要求**

- 清空登录态（走 store，不要直接 `localStorage.removeItem`）。
- 用 `router.push` 跳登录页，**带 `redirect` 参数**记住原地址。
- 并发的多个 `401` **只跳转一次**，只提示一次。
- 不允许出现 `window.location.href`。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 地址集中 | 全项目搜 `http://`，只在 `.env` 文件里出现 |
| 无裸 axios | 组件与 store 里搜 `axios`，搜不到（`api/` 除外） |
| 一接口一函数 | 每个接口有独立的、名字表达业务含义的函数 |
| 401 验证 | 手动把 token 改坏，访问任意页面，能正确跳登录页并记住原地址 |

::: details 怎么手动验证 401 不无限跳转
1. 登录后，在浏览器控制台执行 `localStorage.clear()`（或改成插件用的 key）。
2. 在活动列表页点"刷新"。
3. 观察：页面跳到了登录页，**只跳一次**，控制台没有十几条"跳转"日志。

如果出现反复跳转，检查拦截器里有没有做"正在跳转"的标记。
:::

### 练习 3 · 列表页接真实接口，补齐四态

把上一单元的活动列表页从"写死的数据"改成"从接口取数据"，
按[案例 04](/unit10/06-case-fetch) 的四态模板实现。

**四态的验收内容**

| 状态 | 怎么触发 | 页面应该显示 |
| --- | --- | --- |
| 加载中 | 正常请求发出后 | 转圈或"正在加载"，不能同时显示"没有活动" |
| 出错 | mock 里返回 `code` 非 `200`，或断开网络 | 错误说明 + 重试按钮，**重试按钮真的能用** |
| 空数据 | 筛选一个没有结果的条件下 | "还没有活动" + 一个可点的动作 |
| 有数据 | 正常情况 | 列表，`v-for` 用业务 id 作 key |

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 四态齐全 | 四种状态都能手动触发出来，截图留证 |
| 顺序正确 | 加载中时不闪"没有活动"；出错时不显示"没有活动" |
| 错误提示一次 | 出错时全局只弹一条提示，页面错误态与 toast 不重复 |
| 重试可用 | 点重试按钮能重新发起请求，成功后有数据 |

::: tip 用 mock 主动制造错误
在 mock 里加一个开关，方便演示三种错误：

```js [mock/activity.js（节选）]
if (query.mode === 'error') {
  return { code: 5000, message: '服务器开小差了', data: null }
}
if (query.mode === 'empty') {
  return { code: 200, message: 'success', data: { list: [], total: 0 } }
}
```

这样你不用真去断网，就能把四态一个个演示出来。
:::

## 选做题

### 练习 4 · 请求竞态防护

给活动列表页加上竞态防护，用"加 3 秒延迟的慢接口"验证快速切页不会串数据。

**做两遍，对比两种方案**

| 方案 | 做法 | 观察什么 |
| --- | --- | --- |
| 序号标记 | 每次请求领一个自增号，回来时比对 | 网络面板里旧请求仍然走完，只是结果被丢弃 |
| `AbortController` | 新请求发出前取消旧请求 | 网络面板里旧请求显示为 `canceled` |

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 能复现 bug | 先不加防护，用慢接口复现出"点了第二页显示第一页数据" |
| 修好了 | 加上防护后，快速连点三页，最终显示的一定是最后点的那一页 |
| 有对比记录 | 写下两种方案的差异，至少三条 |
| 边界情况 | 加载态不会卡住，取消的请求不弹错误提示 |

::: details 怎么造出"后发先至"
在 mock 里让延迟由参数决定：

```js
const delay = Number(query.delay) || 0
await new Promise((resolve) => setTimeout(resolve, delay))
```

请求时第一个用 `delay=3000`，第二个用 `delay=300`。
第一次请求在 3 秒后才回来，第二次在 0.3 秒就回来了 —— 后发先至，竞态必现。
**把 3 秒那次请求的结果丢弃或取消掉，才算修好。**
:::

::: warning 别用 `setTimeout` 假装慢接口就以为修好了
如果防护代码里判断错了 `aborted` 的时机，页面可能只是"恰好"显示对了。
**多用几组延迟组合试**：3000 配 300、3000 配 3000、500 配 2000，
三种都要保证最终显示正确。
:::

## 自检标准

做完本单元练习后，逐条自查：

- [ ] 能说出一份数据该放组件内部、props、provide/inject 还是 Pinia 的判断依据
- [ ] 项目里有一个完整的登录态模块，包含 token、用户信息、登录、退出
- [ ] 登录态模块只持久化该持久化的字段，刷新后能自动恢复
- [ ] 退出登录时，内存状态与 `localStorage` 都被清干净
- [ ] 有一个统一的请求层，基础地址从环境变量读
- [ ] 请求拦截器会自动注入 token，页面里不用手写
- [ ] 响应拦截器会剥数据、判业务码、统一提示错误
- [ ] `401` 用 router 跳转并记住原地址，且不会无限跳转
- [ ] 项目里搜不到散落的接口地址，`api/` 之外没有裸 `axios`
- [ ] 活动列表页四态齐全，出错有可用的重试入口
- [ ] 组件用 `storeToRefs` 解构状态，改数据页面能立刻响应
- [ ] 第 10 周链路验证过一遍：未登录被拦 → 登录后回原地址 → 退出后再次被拦

全部打勾，这个单元过关。

## 常见问题

::: details 我的接口地址是别人的电脑，同学访问不到怎么办
接口地址不要写死成 `http://192.168.1.x`。两种做法：

1. **用 mock**：`vite-plugin-mock` 在本地起接口，不依赖任何人。
2. **用代理**：在 `vite.config.js` 里配 `server.proxy`，
   把 `/api` 转发到后端地址。这样接口地址在代码里始终是 `/api`。

**验收时用 mock 的项目一样算过关** —— 重点是请求层的结构与错误处理，
不是"有没有真后端"。
:::

::: details 用 `pinia-plugin-persistedstate` 时 `paths` 报错
`paths` 是旧版（v3 及更早）的配置名，新版（v4 起）改名叫 `pick`。
先确认装的版本：`pnpm list pinia-plugin-persistedstate`，
然后按版本用对应的名字。**本课程以 `pick` 为准。**
:::

::: details `storeToRefs` 解构出来的方法调用不了
`storeToRefs` 只处理状态（`ref`、`computed`），**方法会被跳过**，
所以解构不到方法不是 bug。正确做法是方法直接用 store 调：
`authStore.logout()`。
:::

::: details 刷新后登录态没了，但我明明配了持久化
按顺序排查：

1. 插件注册了吗？`pinia.use(piniaPluginPersistedstate)` 在 `main.js` 里有没有。
2. `persist` 配置写在哪？组合式写法是 `defineStore` 的**第三个参数**，
   不是 `return` 里。
3. `localStorage` 里有没有对应的 key？打开开发者工具 → Application → Local Storage 看一眼。
4. 状态是不是通过 store 改的？如果直接改了别的副本，`watch` 不会触发。
:::

::: details 为什么 `localStorage` 里存的是 `"[object Object]"`
写入时忘了 `JSON.stringify`。用插件不会遇到这个问题（它内部处理了序列化）；
手写持久化时读写要成对：写 `JSON.stringify`，读 `JSON.parse`。
:::
