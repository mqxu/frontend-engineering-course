# 用户端 · uni-app 实战

管理端做完之后，你会发现一个尴尬的事：组织者能在电脑上发布活动了，学生却还得打开电脑才能报名。

**这一栏补上另一半 —— 用手机报名的学生端。**

## 两个端，一套后端

校园活动服务平台有两个使用者，他们的处境完全不同。

| | 管理端 | 用户端 |
| --- | --- | --- |
| 用的人 | 学生干部、社团负责人、审核老师 | 全校学生 |
| 在哪用 | 电脑浏览器，坐在桌前 | 手机，随时随地 |
| 主要动作 | 发布、审核、排场次 | 看活动、报名、查结果 |
| 页面量 | 12 个 | 5 个 |
| 频次 | 一周几次 | 一天可能看几次 |

**它们连的是同一个后端、同一套接口约定。** 管理端的 `docs/project/api.md` 里的 `code` 约定、错误码、分页结构，用户端一条不改地沿用。

这一点决定了整件事的性质：**这不是另起一个项目，而是同一个项目的第二个前端。**

## 为什么不直接写个手机版网页

你也可以给管理端的样式加上媒体查询，让它在手机上勉强能看。但我们不做，有三个原因。

**原因一：学生要的不是“能看”，是“顺手”。** 手指点的东西和鼠标点的不一样 —— 要更大的点击区、要能下拉刷新、要能滑动返回。这些在桌面端的框架里做出来很别扭。

**原因二：微信小程序才是学生真正会打开的入口。** 让他们输网址、登录、收藏，大部分人不会做第二次；扫码或从微信里点开一个小程序，门槛低得多。

**原因三：一套代码要能出多端。** 用 uni-app 写的这份代码，同一套可以编译成 H5（浏览器直接开）、微信小程序（扫码就用）、App（打包上架）。**这才是这一栏要教的核心能力：一套代码，多端运行，以及多端之间那些不能共用的部分到底有哪些。**

## 技术选型

| 类别 | 选型 | 版本 |
| --- | --- | --- |
| 跨端框架 | uni-app（Vue 3 版） | 编译器 3.0.0-5020420260813003 |
| 构建 | Vite（由 uni-app 编译器锁定） | 5.2.8 |
| 框架 | Vue | 3.4.21 |
| UI 组件库 | Wot UI（`@wot-ui/ui`） | 2.3.2 |
| 样式 | sass | 1.104.1 |
| 包管理 | pnpm | 12.4.1 |

### 一个必须提前说清的事实：两个端的版本不一样

这是学生第一次对照教程时最容易懵的地方：

| 项 | 管理端 | 用户端 | 为什么 |
| --- | --- | --- | --- |
| Vite | 8.3.0 | 5.2.8 | uni-app 的编译器自己锁定了 Vite 版本，你改不了 |
| Vue | 3.5.42 | 3.4.21 | 同上，跟着编译器走 |
| 路由 | Vue Router 5 | `pages.json` 配置 | 小程序没有浏览器 history，路由必须是配置式的 |
| UI 库 | Element Plus | Wot UI | Element Plus 是桌面组件，手机上点不动 |
| 请求 | axios | `uni.request` | 小程序没有 XMLHttpRequest，axios 跑不起来 |
| 样式单位 | px | rpx | 手机屏幕宽度差异大，需要一个相对单位 |

**看到 Vite 5.2.8 不要以为教程写错了。** uni-app 是一层编译器，它把 Vue 代码翻译成各个小程序平台能跑的代码，为了兼容十几个平台，它必须锁住一套经过验证的依赖版本。**这是跨端框架的固有代价，不是配置失误。**

顺带说一个实际影响：**你在管理端学到的 Vite 配置技巧，在用户端有一半用不上。** 比如 `vite.config.js` 里能改的东西少得多，很多东西要写在 `manifest.json` 和 `pages.json` 里。

## 怎么跟着做

**前置条件：** 完成管理端，或者至少学完单元 10。理由很实在 —— 请求层怎么设计、状态的四种情况怎么分、错误码怎么用，这些在用户端一模一样要用一遍。**管理端没做过就做用户端，等于同时学两件新东西。**

**建议用时：** 12 到 16 小时。其中建工程和请求层大约占一半 —— 这两块做完，剩下的页面基本是重复劳动。

**不占课内学时。** 48 学时的正课安排不变，这一栏是给学有余力的小组做的第二个端，也适合作为答辩时的加分项。

::: tip 先看一眼成品再动手
第 2 篇讲完就能跑起来一个空白页。**不要等到全部读完才动手**，边读边做，每篇末尾的检查点都过一遍再往下走。
:::

## 你会得到什么

做完这一栏，你应该能：

- 用命令行建一个 uni-app 工程，并说清 `pages.json`、`manifest.json`、`uni.scss` 三个文件各管什么
- 一套代码同时跑在浏览器和微信开发者工具里，并说出哪些写法只在某一个平台上有效
- 用 Wot UI 的组件拼出列表页、详情页、表单页，说明 easycom 为什么不用手写 import
- 把 `uni.request` 封装成带统一鉴权、统一错误处理、Promise 化的请求层
- 处理移动端特有的状态：下拉刷新、触底加载、返回时重新拉数据
- 把 H5 版本部署到服务器，把小程序版本上传成体验版
