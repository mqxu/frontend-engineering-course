## 从一个真实的抱怨说起

第七周你写完了活动列表和活动详情，组件拆得很干净。但到了这周，问题冒出来了。

第一件：你想做一个弹窗组件，发现它只能显示固定的文字和按钮 —— 活动详情页要显示“确认通过这条报名吗”，
审核页要显示“确认驳回并填写理由？”，弹窗里的内容完全不一样，可你在组件里写死了。
要想复用，要么把内容做成一大串 props（`title`、`content`、`confirmText`、`cancelText`……），
要么复制好几份。

第二件：活动详情页里有三层嵌套：页面 → 活动卡片 → 报名按钮。报名按钮要拿到“当前登录用户的角色”
才能决定自己显不显示。你不想从页面一路传 props 传到第三层，中间那层根本不关心这个数据。

第三件：好几个页面都要“把数据存到 localStorage 里并且保持响应”，你发现自己复制了三遍同样的代码，
改的时候还要一个个改。

这三件麻烦事，分别对应这个单元的四个知识点：**插槽、依赖注入、组合式函数、自定义指令**。
它们解决的是同一个大问题：**组件写好之后，怎么让它更通用、让逻辑更值钱。**

::: tip 这个单元的位置
第七周解决的是“组件之间怎么通信”—— props 往下传、emits 往上报，也就是父子通信。
这个单元解决的是“组件怎么变得更通用”—— 内容能不能由使用者决定？深层组件怎么拿数据？
重复的逻辑能不能抽出来复用？

**如果说第七周让你会拆组件，这一周让你会做“能被别人用”的组件。**
:::

| 现场任务 | 1.7 学时 | 分两组：一组做案例 06 的弹窗与通知，一组做 8.5 的三个指令；完成后交换讲评 |
| 复盘 | 0.5 学时 | 展示一份组合式函数，讨论“哪些逻辑值得抽”的判断标准 |

::: warning 最容易混的一个概念
插槽和 props 都能“给组件传东西”，新手最容易混。记住两句话：

- **传数据用 props** —— 组件需要的是“一个值”，比如 `title="活动列表"`。
- **传结构用插槽** —— 组件需要的是“一段界面”，比如“按钮长什么样由你来定”。

判断方法：如果这个内容里含有 HTML 标签或者另一个组件，那就是结构，用插槽。
:::

## 这个单元的产出

**一、可复用弹窗与全局通知**

做成一个能放进任何一个页面的能力：

- 一个用 `Teleport` 送到 `body` 下的模态框，能锁背景滚动、能按 Esc 关闭、关闭后焦点回到原处。
- 一个 `useToast` 组合式函数，任何地方调用 `push('报名审核通过')` 就能弹出一条自动消失的提示。
- 多条通知能堆叠、能手动关闭、进出有动画。

**二、自研组合式函数集**

放在 `src/composables/` 目录下，至少包含：

| 函数 | 作用 |
| --- | --- |
| `useLocalStorage` | 读写本地存储并保持响应，处理序列化与解析失败 |
| `useMouse` | 跟踪鼠标位置，挂载时监听、卸载时清理 |
| `useRequest` | 封装异步请求的加载态、错误态、数据、重试与取消 |

::: details 合格与不合格的差别
**不合格**：三个函数写在同一个文件里，互相调用，每个都依赖组件里的具体业务（比如直接写了
“活动列表接口地址”）。换一个页面就用不了。

**合格**：每个函数一个文件，只依赖传入的参数，不依赖任何业务概念。`useLocalStorage('draft', '')`
在活动编辑页能用，在报名表单页也能用。**判断标准是“能不能原样搬到另一个项目里”。**
:::

## 术语约定

| 术语 | 在这里指什么 |
| --- | --- |
| 插槽 | 组件模板里用 `<slot>` 留出的位置，用组件的人往里填内容 |
| 依赖注入 | `provide` 往下提供值、`inject` 往上取值的机制 |
| 组合式函数 | 以 `use` 开头的函数，内部封装状态与逻辑，返回可用的值 |
| 自定义指令 | 以 `v-` 开头、注册后能写在标签上的能力，用来直接操作 DOM |
