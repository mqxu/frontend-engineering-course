# 综合项目 · 校园活动服务平台

这一部分是综合项目的**规格文档**。它不是教程，是你们做项目时要照着执行的约定。

## 这是什么项目

**校园活动服务平台 · 管理端** —— 给学生会、社团、学院教务处使用的活动管理后台。

学生用手机报名，组织者在电脑上发布活动、审核报名、安排场次。系统负责三件事：

1. 让活动从创建到结束有一个清晰的状态流程
2. 让名额和报名数之间保持一致
3. 让同一个场地在同一个时段不出现冲突

## 谁在用

| 角色 | 日常做什么 | 系统里的权限 |
| --- | --- | --- |
| 活动组织者 | 发布活动、看报名情况、审核报名、安排场次 | 只能看和管理自己的活动 |
| 审核员 | 审核所有活动的报名、维护场地信息 | 能看所有活动，能审核任何报名 |
| 学生 | 在手机上浏览活动、报名、查看审核结果 | 本期不做管理端功能，只作为报名的来源数据 |

**本期只做管理端。** 学生的报名产生的数据，由后端提供，前端不需要做学生端页面。但你要在列表里看到学生信息、报名记录。

## 主线流程

整条业务主线只有三步：

```
① 活动发布            ② 报名审核              ③ 场次安排
组织者创建活动         学生报名后组织者审核      通过审核的学生参加
设置名额与截止时间      通过则占用一个名额        安排时段与场地
发布后学生可报名        驳回则释放名额            检测时段冲突
```

**这条主线必须在项目里完整跑通。** 其余功能（数据看板、场地维护）是围绕主线的辅助功能。

## 技术约束

规格文档不规定技术选型，但课程有一条基线，不符合的要提前说明理由。

| 类别 | 基线 |
| --- | --- |
| 框架 | Vue 3.5，组合式 API |
| 构建 | Vite 8.3 |
| 路由 | Vue Router 5.3 |
| 状态 | Pinia 4.0 |
| UI 库 | Element Plus 2.14 |
| 请求 | axios 1.20 |
| 包管理 | pnpm |

完整的版本清单见[工具链与版本清单](/appendix/tools)。

**为什么要有这条基线**：全班用同一套技术栈，遇到问题时同学之间能互相帮忙，老师也能快速定位。**如果你的项目有特殊理由要用别的技术（比如你们组已经熟悉 Ant Design Vue），提前说明即可，不是硬性要求。**

## 评分维度

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 功能完整度 | 30% | 主线三步能不能完整走通，边界情况处理了没有 |
| 工程质量 | 25% | 目录结构、代码组织、命名、有没有大量重复代码 |
| 工程化实践 | 20% | 版本控制、代码规范、构建优化、部署上线 |
| 文档质量 | 15% | README 能不能让人跑起来，设计文档有没有取舍分析 |
| 答辩表现 | 10% | 能不能讲清一个技术难点，能不能回答提问 |

**“工程质量”占 25%，比多数人预期的高。** 它不是看你的功能多不多，是看代码能不能给别的人看。
