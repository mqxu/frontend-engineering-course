# 单元 6 课后练习

本单元的练习都是“做出来才算数”的类型。**三道必做题，一道选做题。**
各小节末尾的小练习是帮助理解单点的，这一页的练习是单元级产出，会计入过程性考核。

## 必做题

### 练习 1 · 活动报名表单

做一个学生报名校园活动的表单，字段如下：

| 字段 | 控件 | 校验要求 |
| --- | --- | --- |
| 姓名 | 单行文本 | 必填，2 到 20 个字 |
| 学号 | 单行文本 | 必填，8 到 12 位数字 |
| 手机号 | 单行文本 | 必填，11 位手机号 |
| 活动选择 | 下拉单选 | 必填 |
| 参加场次 | 复选框组（多个） | 至少选一个 |
| 备注 | 多行文本 | 可选，不超过 100 字 |
| 同意条款 | 单个复选框 | 必须勾选才能提交 |

**具体要求**

1. 首次进入页面**不显示任何错误提示**。
2. 每个字段**失焦时**校验一次；之后修改该字段时**实时更新**提示。
3. 错误提示显示在**对应字段的下方**，不是统一显示在表单顶部。
4. 点提交时校验全部字段；不通过时把焦点移到**第一个出错的字段**。
5. 提交中按钮**禁用并显示加载态**，重复点击不会产生两条记录。
6. 没勾“同意条款”时，提交按钮可以保持可点，但点击后要在条款旁边给出提示
   （也可以直接禁用，两种都行，**说明你的选择理由**）。

**提交形式**：一个能独立运行的 `.vue` 组件，放在 `src/views/SignupFormView.vue`。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 取值类型 | 复选框组绑定的是数组；同意条款绑定的是布尔值；其他是字符串 |
| 校验时机 | 首次不报错，失焦后报错，之后实时更新 |
| 提示位置 | 每个错误紧贴对应字段，且错误字段有视觉区分（边框变红等） |
| 提交防护 | 按钮禁用 + 函数内标志两层都写了 |
| 焦点定位 | 提交失败时焦点落在第一个错误字段上 |

::: warning 常见的不合格写法
- 所有错误提示挤在表单顶部一个红框里。
- 一进页面就报“姓名不能为空”。
- 校验函数里从第一条 `if` 到底，只显示第一条错误。
- 提交按钮不置禁用状态，快速点两次产生两条记录。

对照着这四条检查一遍，能避开大部分扣分点。
:::

### 练习 2 · 回车提交与 Esc 清空

给练习 1 的报名表单加上键盘操作：

1. 在任意输入框里按**回车**能提交表单（不用鼠标点按钮）。
2. 按 **Esc** 清空当前表单的全部内容，并且清空后焦点回到第一个输入框。
3. 按 **Esc** 清空前要给一次确认（用 `window.confirm` 就行），避免误清。

**具体要求**

- 回车提交走 `<form>` 的 `submit` 事件，**不要给每个输入框单独加 `keydown.enter`**。
- 说明为什么这样做更好，写两句话放在组件的注释里。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 回车 | 焦点在任意输入框里按回车都能提交，且不会刷新页面 |
| Esc | 只在表单区域内按 Esc 才清空，在别的地方按不受影响 |
| 焦点 | 清空后焦点回到第一个输入框 |
| 说明 | 组件里有注释说明为什么用 `submit` 而不是逐个监听 `keydown` |

::: tip 提示
“只在表单区域内按 Esc 生效”有两种做法：把 `@keydown.esc` 写在 `<form>` 上，
或者写在第一个输入框上。先想清楚两者的差别 —— **写在 `<form>` 上时，
只有焦点在表单内部的元素上才会触发**，这正好是你要的效果。
:::

### 练习 3 · 给已有组件补上副作用清理

从你之前写的作业里挑一个组件（没有的话用下面这个），补上完整的副作用清理。

```vue [src/components/SignupCounter.vue（待修复）]
<script setup>
import { ref, onMounted } from 'vue'
import { fetchSignupCount } from '@/api/activity'

const count = ref(0)
const online = ref(true)

onMounted(() => {
  // 每 10 秒刷新一次报名人数
  setInterval(async () => {
    count.value = await fetchSignupCount()
  }, 10000)

  // 网络状态变化时更新提示
  window.addEventListener('online', () => (online.value = true))
  window.addEventListener('offline', () => (online.value = false))

  // 页面滚动时记录位置
  window.addEventListener('scroll', () => {
    document.title = `已滚到 ${window.scrollY}`
  })
})
</script>
```

**具体要求**

1. 找出上面这段代码里**所有**会产生副作用的地方（不止三处）。
2. 逐一补上对应的清理代码，写进 `onUnmounted`。
3. 写一份“副作用清单”，格式用两列表格：**我做了什么 / 对应的清理动作**。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 完整性 | 定时器、三处监听、页面标题的恢复，一个不漏 |
| 函数引用 | `removeEventListener` 用的是和 `addEventListener` 同一个函数引用 |
| 滚动处理 | 滚动监听有节流处理（`requestAnimationFrame` 或时间戳） |
| 副作用清单 | 每条都能对应到具体代码行 |

::: danger 一个容易被漏掉的地方
`document.title` 被改了，但组件卸载后没人恢复它。**这算不算副作用？**

算。判断标准是“我改了一个不属于我的东西”。这个组件改了全局的页面标题，
卸载时就该把它恢复。类似的情况还有：修改了 `document.body` 的样式类、
往 `localStorage` 写了全局键。**凡是改到组件之外的东西，都要想着恢复。**
:::

## 选做题

### 练习 4 · 把报名表单改成两步

把练习 1 的表单拆成两步：

| 步骤 | 字段 |
| --- | --- |
| 第一步 · 学生信息 | 姓名、学号、手机号 |
| 第二步 · 报名信息 | 活动选择、参加场次、备注、同意条款 |

**具体要求**

1. **每一步独立校验**：第一步不通过，不能进入第二步。
2. **可以返回上一步**，返回后**已经填过的数据不能丢**。
3. 第二步要能显示第一步填过的信息摘要，方便核对。
4. 最后一步提交时，**两部分数据一起提交**。
5. 有一个步骤指示器，显示当前是第几步。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 数据不丢 | 从第二步返回第一步，再前进，之前填的值都还在 |
| 独立校验 | 第一步的错误不会在第二步弹出；第二步入到一半返回，第一步的错误也不该莫名出现 |
| 步骤状态 | 当前步骤有明确标识；已完成的步骤与未开始的步骤有区分 |
| 提交 | 最终提交的是一份完整数据，不是两次请求 |

::: tip 参考思路
用一个 `step` 存当前步骤（`1` 或 `2`），用 `v-if` 或 `v-show` 切换两组字段。

**选哪个？** 先想清楚差别：

- `v-if` 会**销毁**当前组的 DOM，切回来要重新渲染。
- `v-show` 只是隐藏，DOM 一直存在。

数据不丢的关键在于**数据存在 `form` 对象里，而不是存在输入框里**。
只要 `form` 不重建，用 `v-if` 也不会丢数据 —— 因为 `<input>` 的值是从 `form` 来的。
想明白这一点，这个练习的主要难点就解决了一半。

完整的实现思路可以参考[案例 07 多步表单](/cases/07-wizard)。
:::

### 练习 5 · 给表单加一个“草稿”

需求：报名填到一半关掉页面，下次打开时内容还在，并且弹出一句“已恢复上次未提交的内容”。

**参考思路**：参照[案例 05 的草稿保存](/unit06/06-case-markdown)，
用 `watch` 加防抖写入 `localStorage`，`onMounted` 时读取。

两个必须处理的问题：

1. **提交成功后要清掉草稿**，否则下次进来会恢复一份已经提交过的内容。
2. **草稿的键要带业务标识**，比如加上活动编号，不然用户在两个活动之间报名会互相覆盖。

## 自检标准

- [ ] 首次进入页面没有任何错误提示
- [ ] 错误提示紧贴对应字段，且错误字段有视觉区分
- [ ] 提交时有禁用按钮与函数内标志两层防护
- [ ] 提交失败时焦点落在第一个错误字段
- [ ] 回车能提交，Esc 能清空，且用的是 `<form>` 的 `submit`
- [ ] 定时器、事件监听、在途请求都有对应的清理代码
- [ ] `removeEventListener` 用的是同一个函数引用
- [ ] 能说出 `input` 与 `change` 的区别，并在代码里用对了时机

## 常见问题

::: details 错误提示为什么会“闪一下就不见了”
通常是 `validateField` 里先把 `errors[field]` 清了、再赋值，中间触发了渲染。
或者 `writable computed` 的 getter 里做了校验。**校验是“读”，不该写在 getter 里。**

检查一下你的 `validateField` 是不是只在事件处理（`@input`、`@blur`、提交）里调用，
而不是在模板表达式中调用。
:::

::: details 为什么我的错误提示只在提交时出现，改动时不更新
因为 `touched` 只在提交时才被置为 `true`。`onFieldInput` 里的判断
`if (touched.value[field])` 一直是假。

**解决**：`onFieldBlur` 里也要把该字段置为 `touched`。这样用户碰过并离开过之后，
再回来修改就会实时提示。
:::

::: details 表单里的 `<select>` 加了 `v-model` 但选不动
三种可能：

1. 绑的 `ref` 初值是 `null`，而 `<option>` 的 `value` 都是字符串，两者对不上。
   改成 `ref('')`。
2. 多选下拉忘了写 `multiple`。
3. `<option>` 没写 `value`，此时 `option` 的文本会被当作值 —— 如果文本里有空格或换行，
   匹配就会失败。

**排查方法**：在 `watch` 里打印一次绑定的值，看看用户选择时它变了没有。
:::

::: details 滚动同步写完之后右侧滚不动
检查三件事：

1. 预览区的 CSS 有没有设置固定高度和 `overflow-y: auto`。没有高度就没有可滚动的空间。
2. `srcMax` 是不是 0（左侧内容太短）。前面的实现里判断了 `srcMax <= 0` 直接返回。
3. `syncScroll` 是不是绑在了 `textarea` 上，而 `textarea` 自己的滚动事件确实会冒泡。

先临时在 `syncScroll` 里 `console.log(ratio)`，看它有没有被调用、值是不是合理。
:::

::: details 草稿功能让输入变卡了
`localStorage` 是同步的，写入会阻塞主线程。检查两点：

- 防抖时间是不是太短（建议 500 到 1000 毫秒）。
- 是不是在 `watch` 里同时做了别的事（比如每次都 `JSON.stringify` 一个大对象）。

**如果内容很大**，考虑改用 `IndexedDB`，它是异步的。不过活动详情这类几 KB 的文本，
`localStorage` 加防抖完全够用。
:::
