## 先看一个真实的报修单

学期初，活动运营的同学提了一个问题：

> “我们那个活动报名页面，学生点两次提交就报了两条报名记录；备注框里打完字，切换输入法之后第一段字没了；手机号那一栏我填了 13800000000，提交上去变成了数字，后台校验又说格式不对。”

这三个问题，一个属于**重复提交**，一个属于**输入法组合期的事件处理**，一个属于**表单取值的类型**。
它们看起来互不相关，其实指向同一个能力：**你知不知道用户的一次操作，在浏览器里到底发生了什么，Vue 又替你做了什么。**

这个单元就解决这件事。

## 为什么表单值得单独讲一个单元

前面四个单元，数据都是你写的：你在 `setup` 里定义一个数组，页面就渲染出列表。
从这一单元开始，**数据由用户产生**。用户产生数据的方式比你想的多：

| 用户动作 | 触发的事件 | 数据在哪 |
| --- | --- | --- |
| 在文本框打字 | `input`、`change` | `event.target.value` |
| 勾选复选框 | `change` | `event.target.checked`，多选还要分组 |
| 从下拉框选一项 | `change` | `event.target.value` |
| 按回车提交 | `keydown`、`submit` | 关键在于阻止默认行为 |
| 把表格内容粘进来 | `paste` | 剪贴板文本，还可能是多行 |
| 滚动到页面底部 | `scroll` | 需要节流，还要清理监听 |
| 窗口尺寸变化 | `resize` | 组件卸载时忘了取消就会出问题 |

而这批数据一旦“乱”起来，代价比列表渲染大得多：**列表渲染错了，页面显示不对；表单数据错了，会写进数据库。**

所以这个单元的定位是：**把用户输入变成可靠的数据。**

## 这次课的 4 学时怎么用

| 环节 | 时长 | 做什么 |
| --- | --- | --- |
| 检查预习 | 0.3 学时 | 抽问：`input` 和 `change` 有什么区别？为什么提交表单要 `preventDefault`？ |
| 讲解 | 1.4 学时 | 重点讲 6.1 的事件对象与 6.3 的取值类型表；6.2 与 6.4 讲清“拦掉的是什么”和“校验顺序” |
| 现场任务 | 1.8 学时 | 两人一组做“活动报名表单”，至少覆盖三种元素类型与两类校验规则 |
| 复盘 | 0.5 学时 | 挑两组演示，重点看错误提示的位置与重复提交有没有防住 |

::: warning 这次课最容易含糊过去的三个点
1. **`input` 与 `change`** —— 很多人以为是一回事，写校验时用了 `change`，结果用户边打字边看不到提示。
2. **多个复选框的 `v-model`** —— 不在 `v-model` 上写数组初值，点一个选项其他的也跟着变，还看不懂原因。
3. **副作用清理** —— 定时器、`resize` 监听、没取消的请求。开发时看不出来，一上线就是“内存一路涨”。
:::

## 开始之前

这一单元要求你先掌握前两个单元的内容，具体是：

- **单元 4**：`ref` 怎么声明、模板里怎么取值、`@click` 是什么。这些是事件处理的地基。
- **单元 5**：`computed` 与 `watch`、`v-if` 与 `v-for`、`v-for` 的 `:key` 怎么写。校验与列表渲染会用到。

如果这两块还没做熟，建议先回去把 [4.4 `ref` 与 `reactive`](/unit04/04-reactivity) 和
[5.1 计算属性与缓存](/unit05/01-computed) 的练习做完。

另外准备两样东西：

1. **Chrome 或 Edge 浏览器**，会用 DevTools 的 Elements 面板看元素属性 —— 讲 `v-model` 本质时会用到。
2. **一个能跑起来的 Vue 3 项目**。还没建的话，按 [2.4 构建工具与 Vite](/unit02/04-vite) 用 `create-vue` 建一个。

## 这个单元的两个产出

课程要求这次课交两样东西，考核时都会看。

**一、多步预订表单**

不是“能填就行”的表单，而是一个**分两步**的场地预订表单：第一步填活动与时段，第二步填联系人与备注。
要求：

| 项目 | 要求 |
| --- | --- |
| 分步 | 每一步独立校验，第一步不通过不能进第二步 |
| 可回退 | 能返回上一步，**已经填过的数据不能丢** |
| 提交 | 提交中按钮禁用，重复点击不会产生两条记录 |
| 错误提示 | 错误显示在对应字段下方，不是弹一个“输入有误” |

**二、Markdown 编辑器**

左侧输入、右侧实时预览的编辑器。要求：

| 项目 | 要求 |
| --- | --- |
| 语法 | 至少支持标题、粗体、斜体、列表、链接、代码块 |
| 工具栏 | 点按钮能在光标处插入语法，**光标位置要回到插入内容之后** |
| 安全 | 预览用 `v-html` 渲染，渲染前必须先把用户输入转义 |
| 草稿 | 刷新页面后草稿还在 |

::: tip 这两个产出其实是同一件事
多步表单练的是**把输入变成可信数据**，Markdown 编辑器练的是**把输入变成安全内容**。
两条线都绕不开“用户是可以随便输入的”这个前提。
:::

## 读完之后

这个单元结束时，你应该能对着一个表单说出三句话：

1. 这个输入框的 `v-model` 绑的是**什么类型**的值。
2. 校验在**什么时候**跑，错误提示**显示在哪**。
3. 这个组件**创建了什么副作用**，在**哪里**清理掉。

下一单元进入[单元 7：组件基础与父子通信](/unit07/)。到那时你会把这一单元的表单拆成组件，
让子组件负责输入、父组件负责数据 —— 而这三个问题的答案，正是拆分时最先要交代清楚的东西。
