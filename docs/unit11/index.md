## 前面十个单元攒下的东西，这一节开始用

到这里，你已经会写组件、会配路由、会管状态、会封请求层。但这些能力是分开练的 —— 每个单元一个小练习，做完就丢。

真实项目不是这样。真实项目是给你一段业务描述，让你自己判断：**要做几个页面？每个页面归哪个路由？数据从哪个接口来？哪些状态要放到全局？**

这个判断过程没法靠背 API 学会，只能做一遍。

所以单元 11 和单元 12 不再讲新语法。这两次课的任务是：**把前面十次课的工具，全部装到一个真实项目上，把它做出来。**

::: tip 这两次课的节奏
单元 11（第 11 周）：**从需求到页面，把骨架搭起来，做出第一个完整业务模块。**
单元 12（第 12 周）：**联调、优化、部署、答辩，把它交出去。**
:::

## 综合项目是什么

**校园活动服务平台 · 管理端** —— 给学生会和社团用的活动管理后台。

一条主线贯穿全部功能：

```
活动发布  →  报名审核  →  场次安排
```

两个角色：

| 角色 | 能做什么 |
| --- | --- |
| 活动组织者 | 创建活动、提交发布、查看自己活动下的报名、给报名记录审核、安排场次与场地 |
| 审核员 | 查看全部活动、审核报名（通过 / 驳回）、维护场地信息 |

五个功能模块：

| 模块 | 对应路由 | 本单元 / 单元 12 |
| --- | --- | --- |
| 登录鉴权 | `/login` | 单元 12 联调时串起来（单元 9 已练过） |
| 活动管理 | `/activity` | **本单元重点**：列表页 + 表单页 |
| 报名审核 | `/signup` | 单元 12 参考实现 |
| 场次与场地 | `/session`、`/venue` | 单元 12 参考实现 |
| 数据看板 | `/dashboard` | 单元 12 参考实现 |

完整的业务规则见[综合项目 · 业务规则与状态流转](/project/rules)。**这个单元动笔之前先把它读一遍**，不然后面写代码时会反复推翻自己。

::: tip 项目还有第二个端
学生用的手机端（uni-app 写的用户端）不在这个单元的范围内 —— 它不占课时，
是管理端跑通之后的延伸内容。想做的同学做完单元 12 再进[用户端专栏](/mobile/)，
从“为什么是 uni-app”顺序读。两端的页面清单和接口约定都在项目文档里，见[用户端需求规格](/project/mobile)。
:::

## 这个单元的产出

这次课要交三样东西，都能直接进最后的项目仓库：

**一、项目页面清单与接口清单**

一张表，覆盖你负责的模块。每行是“页面 → 路由 → 主要接口 → 涉及角色”：

| 页面 | 路由 | 主要接口 | 可访问角色 |
| --- | --- | --- | --- |
| 活动列表 | `/activity` | `GET /api/activities` | 组织者、审核员 |
| 活动详情 | `/activity/:id` | `GET /api/activities/:id` | 组织者、审核员 |
| 新增活动 | `/activity/create` | `POST /api/activities` | 组织者 |
| 编辑活动 | `/activity/:id/edit` | `PUT /api/activities/:id` | 组织者 |

这份表不是交差用的，它是你下一步写路由表的直接依据。**页面清单写不准，路由表一定写乱。**

**二、可运行的工程骨架**

判定标准只有一条：`npm run dev` 起来之后，左侧菜单能点，点了内容区会切换，刷新页面停在原地（不是跳回首页）。内容区是空白的 `<RouterView />` 也没关系。

**三、活动管理模块的列表页与表单页**

要求：

| 要求 | 说明 |
| --- | --- |
| 列表有查询 | 至少两个查询条件（关键字、状态），点“查询”生效 |
| 列表有分页 | 页码、每页条数都要能用 |
| 四态齐全 | 加载中、成功有数据、成功无数据、请求失败，四种都要能看到 |
| 表单能校验 | 必填、长度、名额为正整数、截止时间必须晚于当前时间 |
| 新增与编辑共用 | 同一个表单组件，靠路由参数区分 |
| 提交后回到列表 | 并提示结果，列表刷新 |

::: details 页面清单写得好不好，看这三个标准
**一、每个页面有且只有一个主要职责。** “活动详情”和“编辑活动”是两个页面，因为一个是读、一个是写。合并成一个页面会导致权限判断和状态清理都变复杂。

**二、路由能体现出层级。** `/activity/:id/signups` 比 `/signup-list?activityId=3` 好，因为前者一眼能看出报名是挂在活动下的，面包屑也能自动生成。

**三、清单能反推出接口。** 页面清单写完，接口清单应该基本同时写完。如果需要另外想一遍，说明你的页面拆得和数据结构对不上。

反过来说，最常见的错误是把“活动列表”拆成“我发布的活动”“全部活动”“已下架活动”三个页面。这三个页面结构完全一样，只有筛选条件不同 —— 应该是一个页面，靠查询参数区分。
:::

## 开始之前

这个单元有前置条件，缺一个都会卡住：

- **前十个单元的代码你是自己写的。** 如果你单元 9 的路由是抄的，这里会卡在“为什么菜单点不动”。卡住了就回去补，不要硬撑。
- **项目已经建好 Git 仓库并且完成了第一次提交。** 单元 11 的改动量很大，没有版本控制，改崩了只能重来。
- **已经读完[业务规则](/project/rules)和[接口约定](/project/api)。** 这两个页面是本单元所有代码的依据。
