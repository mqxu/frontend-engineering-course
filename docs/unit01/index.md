## 为什么第一节课不讲代码

先看一段真实对话。学生问："老师，为什么我写的页面在别人电脑上打不开？"
答案通常是"你少装了个包"或者"你 Node 版本不对"。学生接着问："那我怎么知道他需要什么？"
—— 问题就出在这里：**他不知道一个前端工程到底需要哪些东西才能跑起来。**

这就是工程化要解决的第一类问题：**让一个项目在任何一台干净机器上都能按同样的方式跑起来。**

所以这门课第一节课不写业务代码，而是先回答三个问题：

1. 前端是怎么从"一个 HTML 文件"变成"一套工程"的？
2. 工程化到底在解决哪些问题？（六类，后面每个单元都会对上其中某一类）
3. 我需要什么环境，怎么确认环境是好的？

::: tip 一句话概括这个单元的作用
**先看清全局，再动手。** 知道每个工具是为什么存在的，后面学配置的时候才不会背命令。
:::

::: warning 这次课最容易出问题的环节
环境搭建看起来简单，实际上是全课程**最容易卡住的环节之一** —— Node 装不上、pnpm 装完不生效、
Windows PowerShell 禁止执行脚本，都会在这里遇到。

建议：**装之前先通读 [1.4](/unit01/04-environment)，装的时候每步都跑一遍验证命令。**
不要一口气装完再回头验证 —— 一旦某一步错了，后面全部跟着错，排查成本翻倍。
:::

## 开始之前

这个单元不需要任何前端基础，但需要三样东西：

- **一台能装软件的电脑**：Windows 10 以上、macOS 12 以上都可以，8 GB 内存以上。
- **能上网**：下载 Node 与依赖需要网络。如果宿舍网络不稳，可以先用手机热点把 Node 装好。
- **一个记录工具**：记事本、Notion、Markdown 文件都行。环境搭建过程中会遇到各种报错和解决办法，
  记下来。**这一次记的东西，会在这门课里反复用上。**

## 这个单元的产出

按课程要求，这次课要交两样东西：

**一、环境自检报告**

不是截图堆砌，而是一份能用文字说明"我的环境是什么状态"的记录。至少包含：

| 项目 | 要求 |
| --- | --- |
| 版本信息 | Node、npm、pnpm、Git 各自的版本号 |
| 安装方式 | 用的是什么工具装的（fnm / nvm / 直接安装包） |
| 遇到的问题 | 至少写一条：遇到什么报错、怎么解决的 |
| 自检结果 | [1.4 末尾的清单](/unit01/04-environment)逐项打勾的情况 |

**二、个人学习路线图**

用一页纸说明三件事：

1. 你在[三阶段路线](/guide/learning-path)的哪一站（打地基 / 上装备 / 定方向）。
2. 哪些能力项你已经过关，哪些还不行 —— **判断标准是"能不能独立做出来"，不是"看没看过教程"**。
3. 这门课结束后，你想往哪个方向继续深入（业务开发 / 跨端 / 服务端渲染 / 质量与工程 / 可视化）。

::: details 一份合格的路线图长什么样
去年有位同学的路线图是这样的（节选）：

> 当前位置：**第一阶段末尾**。
> 已过关：HTML 结构、CSS 布局（能不看资料做响应式）、JS 基础语法与数组方法。
> 未过关：Promise 只看得懂不会写；没碰过 Git；不知道 package.json 是什么。
> 本课程目标：把工具链和 Vue 补上，能独立交付一个带登录的项目。
> 之后方向：跨端开发，想往小程序方向走，准备寒假学 uni-app。

**注意它的特点**：诚实、具体、有可验证的标准（"只看得懂不会写"没算过关）。
最没用的写法是"HTML 熟练、CSS 熟练、JS 熟练" —— 这种既不诚实也没法指导下一步。
:::
