## 先回答一个绕不开的问题

第 1 周你按清单把 Node 装好了。现在问一句：**Node 是干什么的？**

不少同学的回答是“写后端的”。这个印象来自各类 Node 教程 —— 它们教你用 Node 起一个
HTTP 服务、连数据库、写接口。于是就有了下面这段对话。

> 学生：我又不写后端，为什么要学 Node？
> 老师：你上一节课装的 `pnpm`，是怎么运行的？
> 学生：……在命令行里敲的。
> 老师：命令行里的 `pnpm`，就是一个用 Node 写的程序。

**Node 在这门课里的角色是“工具链的运行环境”**，不是“后端语言的运行环境”。
`pnpm`、`vite`、`eslint`、`vitest`、`tsc` —— 这些你每天要用的工具，本质都是
JavaScript 程序，需要有人把它们跑起来。Node 就是那个人。

这个关系可以类比成 `exe` 与 Windows：

| 类比 | 对应到前端 | 说明 |
| --- | --- | --- |
| 一个 `.exe` 文件 | 一段 JavaScript 工具代码 | 程序本身 |
| 双击运行 | `node xxx.js` | 需要一个执行环境 |
| Windows | Node | 提供执行环境，不是程序本身 |

你不必会写字处理软件，但你得有一个操作系统才能打开 `.exe`。同理，你不必写后端服务，
但你得装 Node 才能跑起 `vite` 和 `pnpm`。

::: tip 这个单元要改变的一件事
第 1 周你装好了工具，但大概率是“照着命令敲，敲完能跑就算过”。
这个单元要把这些工具**从黑盒变成白盒** —— 知道每个配置文件里的每一行在管什么，
报错时能自己定位到是哪一层出了问题。

这是从“会用”到“能维护”的分界线。也是为什么第 3 周让你自己建项目仓库时，
你能读懂仓库里那些文件，而不是删掉它们。
:::

::: warning 这次课最容易卡住的地方
依赖安装失败。原因通常不在你写的代码里，而在网络、镜像源、Node 版本、缓存这四层。

**不要一遇到报错就删 `node_modules` 重装。** 删掉重装只是把问题推迟到下一次。
正确做法是按 [2.2 的排查顺序](/unit02/02-package-manager#依赖装不上时按这个顺序排查)
一层一层排除，每次只改一个变量，然后记录你改了什么、结果如何。
:::

## 开始之前

需要三样东西，第 1 周应该都准备好了。**如果缺，先补上再往下读。**

- **Node 24 LTS**：`node -v` 输出类似 `v24.9.0`。低于 20.19 会在第 4 周开始的 Vue 项目里出问题。
- **pnpm 12**：`pnpm -v` 输出类似 `12.4.1`。没有的话用 `npm i -g pnpm` 装。
- **一个自己建的练习目录**：不要在桌面随便建，也不要塞进 `node_modules`。
  建议固定在 `~/projects/campus-activity-admin`，后面几周会一直用这个目录。

另外准备一个记录文件。这个单元会故意让你遇到报错，**报错处理不了不是问题，
处理完不记下来才是问题**。

```md [依赖排查单.md（先建个空文件）]
# 依赖排查单

| 时间 | 现象（报错原文） | 试了什么 | 结果 | 最终原因 |
| --- | --- | --- | --- | --- |
| | | | | |
```

## 这个单元的产出

按课程要求，这次课交两样东西。

**一、依赖排查单**

不是“装了个包”的流水账，而是一份**按排查顺序记录的问题档案**。至少包含：

| 项目 | 要求 |
| --- | --- |
| 现象 | 报错原文，完整贴出来，不要只写“报错了” |
| 排查顺序 | 按网络与镜像 → Node 版本 → 权限 → 缓存 → 锁文件的顺序逐项排除 |
| 每次动作 | 一次只改一个变量，写清楚改了什么、结果如何 |
| 结论 | 最终原因是什么；如果再遇到同类问题，第一步该查哪里 |

::: tip 一份好的排查单长什么样
> 现象：`pnpm install` 报 `ERR_PNPM_META_FETCH_FAIL`。
> 排查 1：`ping registry.npmjs.org` 通，说明不是断网。
> 排查 2：访问公司镜像地址超时 —— **怀疑是镜像源**。
> 排查 3：`pnpm config get registry` 输出还是旧的镜像地址。
> 处理：`pnpm config set registry https://registry.npmmirror.com`，重装成功。
> 结论：镜像源失效。这类报错先查 `registry`，再查网络。

注意它的结构：**每一条都只有“做了什么 → 看到什么”**，没有“可能是”“应该是”这类猜测。
:::

**二、可复用的 `vite.config.js`**

一份能直接复制到新项目里用的配置文件，至少包含：

| 配置项 | 要求 |
| --- | --- |
| 路径别名 | `@` 指向 `src`，并在编辑器里也能识别 |
| 开发代理 | 把 `/api` 转发到后端地址，解决本地跨域 |
| 构建输出 | 指定产物目录、资源内联阈值 |
| 代码分包 | 把体积大的库拆成独立 chunk，不全部塞进主包 |
| 环境变量 | 用到 `VITE_` 前缀的变量，并在配置里读取 |

这份配置是第 11 周搭建综合项目时的起点。**写完先自己跑一遍
`pnpm build && pnpm preview`，产物能正常打开才算完成。**
