## 从这一周开始，所有练习都在同一个项目里做

前八周的练习，每个页面基本都是**独立的小实验**：这一周写个计数器，下一周写个列表，
写完就放在一边。从第 9 周开始，规则变了。

**第 9 周起，所有练习都要写进同一个项目仓库 —— 校园活动服务平台管理端。**
前八周写的东西会被一个个接进来：列表页、表单页、组件、组合式函数，
都要在同一个应用里跑起来。

这意味着你要第一次面对“**一个应用有很多页面**”这件事：

- 地址栏输入 `/activities/12`，怎么知道该显示哪份活动详情？
- 没登录的用户访问 `/activities`，怎么把他挡回登录页？
- 审核员访问 `/dashboard`（数据看板），怎么告诉他“你没有权限”，而不是白屏？
- 十几个页面全打进一个文件，首屏要等好几秒，怎么办？

这四个问题的答案都在这一周：**路由**。

::: tip 这一周的分量
路由是“从单页练习到完整应用”的那道门。学完这一周，你就有能力把前八周的所有页面
组织成一个能点、能跳转、有登录的应用 —— 也就是课程要求的“带鉴权的页面骨架”。

**这个骨架是第 10 到 12 周的基础**：单元 10 往里加数据请求，单元 11 填核心业务，
单元 12 联调上线。骨架搭不好，后面每一步都会被牵制。
:::

## 这次课的 4 学时怎么用

| 环节 | 时长 | 做什么 |
| --- | --- | --- |
| 检查预习 | 0.3 学时 | 抽问：单页应用里，地址栏变了但页面不刷新，是怎么做到的？ |
| 讲解 | 1.5 学时 | 重点讲 9.1 的路由表与 9.3 的守卫执行顺序；9.2 以演示为主 |
| 现场任务 | 1.7 学时 | 搭出管理端的完整路由表 + 一个能拦住未登录用户的守卫 |
| 复盘 | 0.5 学时 | 对比两份路由表，讨论“嵌套结构怎么分才合理” |

::: warning 这次课最容易做错的地方
**刷新页面时“先渲染还是先校验”的时序问题。** 用户刷新页面，token 还在本地存储里，
但用户信息需要异步请求才知道。如果判断逻辑写在渲染之后，会先闪一下“未登录”
再跳到登录页 —— 或者反过来，先渲染了受限页面再被踢出去。

正确做法是 9.4 讲的 `ready` 标记：**在应用挂载之前，先把登录态准备好。**
这个坑案例 10 会重点讲，这里先埋个伏笔。
:::

## 开始之前

这个单元假设你已经：

- 会写 Vue 组件、会用一个前端脚手架创建项目（[单元 2](/unit02/04-vite)）。
- 知道 `ref` / `computed` 的基本用法（[单元 4](/unit04/04-reactivity)）。
- 用过 `provide/inject` 或至少理解“跨组件共享状态”这件事（[单元 8](/unit08/02-provide-inject)）。

路由本身不难，难在**把它和登录态、权限、布局组织在一起**。
这也是为什么这个单元放在组件化之后 —— 你得先把组件写好，路由才有东西可以组织。

## 这个单元的产出

**带鉴权的页面骨架**

一个能跑起来的应用骨架，包含：

| 部分 | 要求 |
| --- | --- |
| 路由表 | 覆盖登录、布局、活动列表、活动详情、审核、场次、看板、403、404，全部懒加载 |
| 登录页 | 表单校验、提交中状态、错误提示 |
| 登录态 | token 与用户信息存在一个状态模块里，刷新后能恢复 |
| 守卫 | 未登录访问受限页面会被挡回登录页，并带上原地址 |
| 两级权限 | 菜单级（看不到入口）与按钮级（看不到按钮），都从同一份权限数据推导 |
| 退出登录 | 清掉该清的，回到登录页 |

::: details 合格与不合格的差别
**不合格**：每个页面都能直接访问，登录只是个摆设 —— 在地址栏直接输 `/activities`
照样能进。或者权限判断写了两份，菜单里藏了但路由里没拦，
用户手输地址还能进。

**合格**：无论从菜单点、手输地址还是刷新页面进入，受限页面都会被正确拦住；
菜单、路由、按钮的权限判断来自**同一份数据**，不会出现“菜单看不见但地址能进”的矛盾。
:::

## 术语约定

| 术语 | 在这里指什么 |
| --- | --- |
| 路由 | 地址和页面之间的对应关系；也指管理这套关系的库 |
| 路由表 | 一份配置，列明哪个地址交给哪个组件处理 |
| 动态参数 | 地址里会变的部分，比如 `/activities/:id` 里的 `id` |
| 查询参数 | 地址里 `?` 后面的键值对，比如 `?page=2` |
| 守卫 | 在跳转发生前后执行的函数，用来做拦截和判断 |
| 凭证 | 登录成功后服务端给的 token，之后每次请求都带上它证明身份 |
