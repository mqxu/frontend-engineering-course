# 前端学习路线

学前端最常见的问题不是不努力，而是**不知道自己站在路线的哪个位置** —— 于是今天看 Vue，明天看 React，
后天听说 TypeScript 重要又去翻两天。每样都碰过，每样都做不出东西。

这一页给你一条完整路线，把前端学习拆成三个阶段，并标出本课程的位置。看完你应该能回答两个问题：
**我现在在哪一站，下一站该做什么。**

## 第一阶段 · 打地基

**目标：能用原生技术做出会动的页面。** 对应先修课程，约 60 - 80 学时。

这一阶段的共同点是：**不依赖任何框架**。为什么必须先打地基？因为框架解决的是"怎么组织代码"的问题，
如果连基础的 DOM 操作和异步都没写过，你没法判断框架帮你省掉了什么，只能靠死记 API。

| 能力项 | 过关标准 | 怎么自检 |
| --- | --- | --- |
| HTML | 能凭记忆写出语义化结构，知道表单、列表、表格的常用属性 | 给一张设计图，不查资料写出结构骨架 |
| CSS | 能独立完成响应式布局，理解 Flex 与 Grid、盒模型、层叠与优先级 | 不借助框架，做一个手机和电脑都能看的页面 |
| JavaScript | 掌握变量、函数、数组与对象方法、ES6 模块、异步（Promise 与 async / await） | 手写一个带分页的数据筛选，用 fetch 拿数据 |
| DOM 与调试 | 会用开发者工具定位样式与脚本问题，看得懂控制台报错 | 看到一个报错，能说出它在哪一行、大概什么原因 |
| 工具初识 | 装好编辑器、会开浏览器控制台、知道 Git 是什么 | — |

::: warning 别急着跳过
"我看过 JS 教程"和"我能用 JS 写出东西"是两件事。第一阶段的过关标准统一是**能独立做出来**，
不是看得懂。如果上面的自检题有一半做不出来，先回去补 —— 这门课不会停下来讲 `const` 和 `for` 循环。
:::

## 第二阶段 · 上装备

**目标：用现代工程化方式做项目。** 这就是本课程的 48 学时。

| 能力项 | 过关标准 | 对应单元 |
| --- | --- | --- |
| 工程化认知 | 能说清工程化解决了哪几类问题，知道一个现代前端项目的标准结构 | 单元 1 |
| 工具链 | 能独立初始化工程、读懂 `package.json`、配置 Vite、接上规范与提交钩子 | 单元 2 - 3 |
| 框架核心 | 会用组合式 API 写出响应式交互，能独立排查"数据不更新"一类问题 | 单元 4 - 6 |
| 组件化 | 能按职责拆分组件、设计 props 与事件接口、用插槽提高复用度 | 单元 7 - 8 |
| 应用架构 | 能用路由与状态管理组织多页面应用，封装请求层，实现登录鉴权 | 单元 9 - 10 |
| 交付能力 | 能打包、部署、写交接文档、在答辩中讲清技术决策 | 单元 11 - 12 |

这一阶段有一个明显的转折：**从"写页面"变成"搭工程"**。

在第一阶段，你写的是一个 HTML 文件加一个 JS 文件；在第二阶段，你要管的是几十个源文件、
一份依赖清单、一堆配置，还要保证同事拉下来能跑起来。难度不在于语法变难了，而在于**要考虑的东西变多了**。

## 第三阶段 · 定方向

**目标：按岗位方向深入。** 对应后续课程与自主学习，建议 60 学时以上。

到这一步，基础能力和工程能力都已经具备，接下来是选一条路走深。

| 方向 | 主攻内容 | 典型出口 |
| --- | --- | --- |
| 业务开发 | 组件库二次封装、复杂表单与表格、权限体系、性能优化、TypeScript | 后台管理系统、企业信息化前端 |
| 跨端开发 | uni-app 或 Taro、小程序规范、多端适配与条件编译、原生能力调用 | 小程序、移动端 H5、混合应用 |
| 服务端渲染 | Nuxt 路由与数据获取、SSR 与预渲染、SEO、部署到 Node 服务 | 官网、内容型站点、电商前台 |
| 质量与工程 | Vitest 单元测试、Playwright 端到端测试、CI 流水线、监控与埋点 | 测试开发、前端基础设施 |
| 可视化 | ECharts、Canvas 与 WebGL、大屏适配、数据看板 | 数据可视化、BI 前端 |

本课程在[单元 12](/unit12/) 之后给了一个课外拓展：用 uni-app 把项目里的两个页面移植到移动端。
不占课内学时，是给想往跨端方向走的同学留的入口。

## 一句话说清三个阶段的关系

| 阶段 | 解决的问题 | 关键词 |
| --- | --- | --- |
| 打地基 | 能不能做出东西 | 语言、DOM、调试 |
| 上装备 | 能不能做出**能交付**的东西 | 工程、框架、协作 |
| 定方向 | 能不能做出**别人做不了**的东西 | 深度、领域、性能 |

## 给学生的几句实话

::: tip 别把路线背下来
按"能做出东西"的标准往下一站走就够了。路线图是给自己定位用的，不是考试大纲。
:::

**框架会换，底层能力不会换。**

Vue 2 换到 Vue 3、Vue 换到 React，语法差异一两周就能适应。但 Node 生态怎么运作、模块化怎么组织、
怎么调试一个问题、代码怎么分层 —— 这些东西十年没怎么变，值得花时间。

**官方文档是第一优先级。**

遇到问题的查找顺序应该是：官方文档 → 搜索引擎 → 问人。原因很简单：文档写的是设计意图，
搜到的答案多数是"别人踩坑后的权宜之计"，可能已经过时。

**"看得懂"不算过关。**

路线图上任何一站的过关标准都是**能独立做出来，并且讲清楚为什么这么做**。
对着教程敲一遍能跑，关上教程写不出来，说明还没过关。

## 自测：你现在在哪一站

- 能不看资料写出一个带表单校验的页面吗？→ 不能，在第一阶段。
- 能说清 `package.json` 里 `dependencies` 和 `devDependencies` 的区别吗？→ 不能，准备进第二阶段。
- 换台电脑，能让你的项目在 15 分钟内跑起来吗？→ 不能，第二阶段的工程能力还没到位。
- 能解释你的页面为什么这么分层、这么拆组件吗？→ 不能，还在"能写"和"会设计"之间。
- 能独立排查一个线上白屏问题吗？→ 不能，第三阶段还没开始。
