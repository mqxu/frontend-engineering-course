# 怎么用这套教程

这页说明教程的组织方式与阅读约定。花三分钟看完，后面能省不少时间。

## 教程的三种用法

| 场景 | 怎么读 |
| --- | --- |
| 课前预习 | 读“单元导学”+ 知识点小节，把示例跑一遍，把不懂的地方标出来 |
| 课中动手 | 直接跳到本单元的案例与练习，按步骤做实训任务 |
| 课后复习 | 看“常见坑”自查，做“课后练习”，答不上来再回正文 |

## 每个单元的固定结构

每个单元都是这套结构，位置固定，方便你快速定位：

```text
单元导学          ← 目标、知识地图、这次课的产出
  ↓
知识点小节        ← 编号 1.1、1.2 …… 一节讲透一个问题
  ↓
案例 / 实战       ← 把本节知识点拼成一个能跑的东西
  ↓
课后练习          ← 给思路不给答案
```

## 页面上的几种标记

**代码块右上角标的是文件名。** 看到文件名就说明这段代码要放到那个文件里：

````text
```js [vite.config.js]
// 这个文件名表示：代码写到 vite.config.js 里
```
````

## 排版与术语约定

统一约定是为了减少歧义：

| 写法 | 含义 |
| --- | --- |
| `单元 4` | 第 4 周上课的那个单元，一次课讲完 |
| `第 4 章` | 旧版教程的章节，仅在对照旧资料时出现 |
| `./src/views/` | 以项目根目录为起点的相对路径 |
| 菜单 → 设置 | 从“菜单”进入“设置”，依次点击 |
| `Ctrl + S` | 快捷键，macOS 上对应 `Cmd + S` |

**代码里的版本号都是核对过的。** 文中的依赖版本按 npm 仓库现状核对，教学统一用稳定版，不追预发布版本。
完整清单见[工具链与版本清单](/appendix/tools)。

## 关于示例代码

教程里的代码**都能跑**，但不是每段都要照着抄。三类代码要区别对待：

| 类型 | 怎么处理 |
| --- | --- |
| 完整文件（带文件名的代码块） | 直接抄进项目，按注释改 |
| 片段（只贴关键几行） | 看懂了就行，不用抄 |
| 错误示范（标了"✗"） | **不要抄**，这是用来对比的反例 |

::: warning 抄代码的正确姿势
抄一遍 → 改几个地方 → 看变化 → 说清为什么变化。四步走完，才算学会。
只抄不改，等于把代码从教程搬到编辑器，技能没有发生转移。
:::

## 课后练习怎么算做完

每章练习末尾都有自检标准，标准统一是**能独立做出来**：

- [ ] 能不看教程写出主要代码
- [ ] 能说清为什么这么写，而不是"教程上就是这么写的"
- [ ] 遇到报错能自己定位，不靠问人

三条都打勾，这个单元就算过关。做不到就回看对应小节 —— 教程里每个坑都有说明，
如果还是卡住，多半是前面的某个前置知识没掌握。

## 建议的阅读顺序

如果时间充裕，按顺序读 12 个单元。如果时间紧张：

1. **只想尽快写出页面**：单元 4 → 5 → 6 → 7，跳过工具链，边写边补。
2. **只想弄懂工程化配置**：单元 1 → 2 → 3，配合[单元 12 的构建与部署](/unit12/03-deploy)。
3. **要交项目了**：直接看[综合项目](/project/)和各[案例](/cases/)，缺什么补什么。

不过说实话，最省时间的路径还是按顺序读 —— 后面的内容默认你掌握了前面的东西，
跳跃阅读容易在某个小地方卡住，反而更费时间。
