## 必做题

### 练习 1 · 给待办清单加排序

在[案例 01](/unit05/06-case-crud) 的基础上做两个扩展。

**扩展一：按优先级排序。**

优先级有高、中、低三档。要求：

| 项目 | 要求 |
| --- | --- |
| 排序选项 | 一个下拉框：默认顺序 / 优先级从高到低 / 优先级从低到高 |
| 排序实现 | 用**计算属性**，不要用 `watch` |
| 依赖关系 | 排序发生在筛选之后（先筛出要显示的，再排序） |

**扩展二：按截止时间排序。**

要求同上，另加两条：

- 没有截止日期的任务，无论升序降序都**排在最后**；
- 截止时间相同的任务，保持原顺序（不要出现“每次排序结果都不一样”）。

**提交形式**：完整的 `TaskListView.vue`，外加一份 100 字的说明，
画出你的派生链（哪些是源头、哪些是算出来的）。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 派生链 | 排序是计算属性，全程没有新增 `watch` |
| 排序正确性 | 三档优先级的顺序正确；无截止日期的排最后 |
| 稳定性 | 同优先级的任务相对顺序不变 |
| 组合正确 | 排序和筛选能同时生效 |

::: details 参考思路
优先级排序要先做一次“文本到数字”的映射：

```js
const PRIORITY_RANK = { high: 0, medium: 1, low: 2 }

const sortedTasks = computed(() => {
  const list = filteredTasks.value
  if (sortBy.value === 'priority-desc') {
    return list.toSorted((a, b) => PRIORITY_RANK[a.priority] - PRIORITY_RANK[b.priority])
  }
  if (sortBy.value === 'priority-asc') {
    return list.toSorted((a, b) => PRIORITY_RANK[b.priority] - PRIORITY_RANK[a.priority])
  }
  return list
})
```

**“无截止日期排最后”** 的写法：把没有日期的当成一个极大值。
但注意升序和降序要分开处理 —— 降序时极大值会跑到最前面，
所以不能简单地“给个极大值”，要在比较函数里显式判断：

```js
function compareByDeadline(a, b, dir) {
  // 空值永远排最后，与方向无关
  if (!a.deadline && !b.deadline) return 0
  if (!a.deadline) return 1
  if (!b.deadline) return -1
  return a.deadline.localeCompare(b.deadline) * dir
}
```

**“保持原顺序”**：`Array.prototype.sort` 在现代浏览器里是稳定的，
所以同值时天然保持相对顺序。这也是为什么不能用随机数做 key ——
排序的稳定性依赖“原始顺序”这个隐式信息。
:::

### 练习 2 · 手写一个活动列表页

**从零手写**，不参考[案例 02](/unit05/07-case-grid) 的代码（可以看它的思路）。

**功能要求**

| 功能 | 说明 |
| --- | --- |
| 关键词搜索 | 匹配活动标题 |
| 状态筛选 | 全部 / 草稿 / 报名中 / 报名截止 / 已结束 |
| 表头排序 | 至少两列可排序（报名截止、名额），三态循环 |
| 分页 | 每页 5 条，可上一页 / 下一页 / 直接跳页 |
| 统计 | 底部显示“第 x - y 条，共 n 条” |
| 空数据 | 区分“系统没有活动”和“筛选后没有结果” |

**技术要求**

1. 不使用任何 UI 组件库，表格用原生 `<table>`；
2. 派生链清晰：筛选 → 排序 → 分页，每步一个计算属性；
3. **不允许用 `watch` 来“通知下一步”**；
4. 数据用本地的静态数组（12 条以上，保证能翻页）。

**提交形式**：`src/views/ActivityTableView.vue`。

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 派生链 | 组件里的 `watch` 数量为 0 |
| 页码不越界 | 翻到最后一页后加筛选条件，表格不能空白 |
| 排序不改原数据 | 取消排序后能恢复原顺序 |
| 两个空状态 | 两种空的文案和引导动作不同 |
| 可运行 | `pnpm dev` 无报错、无控制台警告 |

::: warning 三个硬性检查
做完之后自己跑一遍这三条，任何一条不过就不算完成：

1. **全文搜索 `watch`**：除了“四态”里的加载函数，不应该有别的 `watch`；
2. **翻到第 3 页，然后把关键词改成只匹配 1 条**：表格要正常显示那一条，
   页码要显示 1 / 1；
3. **把接口地址改成错的**（如果接了接口）：不能卡在加载中。
:::

### 练习 3 · 给一个页面补齐四态

选一个你写过的数据页面（可以用单元 4 的名片页列表，或者练习 2 的表格页），
按[5.5 的规范](/unit05/05-four-states)补齐四态。

**要求**

| 状态 | 要求 |
| --- | --- |
| 加载中 | 用骨架屏，不用单纯的转圈 |
| 出错 | 说明 + 重试按钮 + 返回入口；错误文案是人能看懂的 |
| 空（系统没有） | 说明 + “去创建”的引导 |
| 空（筛选没有） | 复述当前筛选条件 + “清除筛选”的引导 |
| 有数据 | 正常内容 |

**提交形式**：修改后的组件，外加一份说明，包含：

1. 四态的判断顺序；
2. 每种状态的触发条件；
3. 你是怎么验证“不闪空状态”和“不会卡在加载中”的。

::: details 怎么验证“不闪空状态”
把浏览器开发者工具打开，切到 Network 面板，把网络限速改成 **Slow 3G**，
然后强制刷新页面（`Cmd/Ctrl + Shift + R`）。

**观察点**：从页面出现到列表渲染完成，中间有没有出现过“暂无数据”。

如果出现了，说明判断顺序写反了。**这是最可靠的验证方法**，
比肉眼看代码靠谱。
:::

## 选做题

### 练习 4 · 表单草稿自动保存

用 `watch` 实现一个“表单自动保存草稿到 `localStorage`”。

**需求**

1. 表单有三个字段：活动标题、名额、报名截止时间；
2. 任意字段变化后 **1 秒**内保存一次草稿（防抖）；
3. 页面打开时自动读取草稿并填充，同时提示“已恢复上次的草稿”；
4. 点击“提交”后清空草稿；
5. 提供“清除草稿”按钮，点击后清空表单和存储。

**技术要求**

| 项目 | 要求 |
| --- | --- |
| 防抖 | 用 `setTimeout` + `onCleanup` 清理，不要留下未清理的定时器 |
| 清理 | 组件卸载时不能有未执行的定时器 |
| 容错 | `localStorage` 里存的可能是损坏的 JSON，读取时要 `try / catch` |
| 空值 | 三个字段都为空时不要保存草稿（避免存一个空对象） |

::: details 参考思路
```js
import { reactive, watch, onMounted } from 'vue'

const DRAFT_KEY = 'activity-form-draft'
const form = reactive({ title: '', capacity: '', deadline: '' })
const restored = ref(false)

watch(
  () => ({ ...form }),
  (snapshot, _old, onCleanup) => {
    const timer = setTimeout(() => {
      // 全空就不保存，顺便清掉旧草稿
      const isEmpty = !snapshot.title && !snapshot.capacity && !snapshot.deadline
      if (isEmpty) {
        localStorage.removeItem(DRAFT_KEY)
        return
      }
      localStorage.setItem(DRAFT_KEY, JSON.stringify(snapshot))
    }, 1000)

    onCleanup(() => clearTimeout(timer))
  }
)

onMounted(() => {
  const raw = localStorage.getItem(DRAFT_KEY)
  if (!raw) return
  try {
    Object.assign(form, JSON.parse(raw))
    restored.value = true
  } catch {
    localStorage.removeItem(DRAFT_KEY)   // 损坏的数据直接清掉
  }
})

function submit() {
  // 提交逻辑
  localStorage.removeItem(DRAFT_KEY)
  restored.value = false
}
```

**三个关键点：**

1. **用 `() => ({ ...form })` 作为来源。** 这样每次变化后回调拿到的是一个
   快照（新对象），不会被后续修改影响 —— 正好避开[对象新旧值相同的坑](/unit05/02-watch)；
2. **`Object.assign(form, parsed)` 而不是 `form = parsed`。**
   `form` 是 `reactive` 对象，整体替换会丢响应性；
3. **`try / catch` 不能省。** 用户可能手动改过 `localStorage`，
   里面存的东西不一定是合法 JSON。
:::

**验收标准**

| 项目 | 要求 |
| --- | --- |
| 防抖有效 | 连续输入时只在停下来 1 秒后写入一次 |
| 卸载干净 | 输入后立刻切走页面，控制台无报错 |
| 容错 | 手动把存储值改成乱码，页面能正常打开且清掉脏数据 |
| 空值不存 | 清空所有字段后，`localStorage` 里没有草稿 |

::: details 一个可以顺手做的优化
加上“草稿保存中 / 已保存”的状态提示，让用户知道数据是安全的。

```js
const saveState = ref('idle')   // idle / saving / saved
```

在 `setTimeout` 执行前设成 `saving`，写入成功后设成 `saved`，
两秒后回到 `idle`。**这类“让用户安心”的反馈，在真实产品里很重要。**
:::

## 常见问题

::: details 排序后取消，顺序没有回到最初，怎么办
这是正常的。`toSorted` 返回的是“按比较函数排出来的结果”，
取消排序时如果只是不排序，顺序就是**上一次筛选/排序后的顺序**，
不是最初的原始顺序。

**两种处理：**

1. **接受它。** 大多数产品就是这样，取消排序表示“按数据源的顺序”。
   只要数据源顺序稳定，看到的就是稳定结果；
2. **要严格恢复原顺序**，就得记录原始顺序：

```js
const sourceOrder = new Map(activities.value.map((a, i) => [a.id, i]))

// 取消排序时
return filteredList.value.toSorted(
  (a, b) => sourceOrder.get(a.id) - sourceOrder.get(b.id)
)
```

**注意第 2 种做法的代价**：`sourceOrder` 必须在数据变化时同步更新，
又多了一份需要维护的状态。**除非产品明确要求，否则选第 1 种。**
:::

::: details 分页和筛选能不能放在同一个组件里
可以，但组件会长到两三百行。建议按这个顺序拆：

1. **逻辑抽成组合式函数**（`useTableQuery`），组件只负责渲染；
2. **分页控件抽成子组件**（`Pagination.vue`），接受页码数据和几个事件；
3. **表格行抽成子组件**，接受一行数据。

**拆分时机**：当模板里出现了“两个不相关的小节”时再拆。
过早拆分会让你在多个文件之间来回跳，反而更慢。
组件拆分的判断依据见[单元 7](/unit07/01-sfc)。
:::

::: details 本地筛选需要防抖吗
**不需要。** 12 条数据的 `filter` 耗时在微秒级，
加防抖只会让输入显得卡顿（用户打字后要等一下界面才变）。

**什么时候需要防抖：**

- 筛选或搜索要发接口请求；
- 数据量很大（上万条）且要做复杂运算（比如全文匹配）；
- 筛选会触发很重的渲染（比如上千行的表格）。

**判断方法**：用浏览器性能面板录一段，看输入时的耗时。
**不要凭感觉加防抖，防抖本身也是一种延迟。**
:::

::: details 练习 2 一定要做 12 条数据吗
是。少于 10 条就翻不了页，分页逻辑的边界情况（最后一页只有 1 条、
总数正好是每页条数的整数倍）就测不到。

**这几个边界情况最值得测：**

| 情况 | 要验证什么 |
| --- | --- |
| 总数 12、每页 5 | 最后一页只有 2 条 |
| 总数 10、每页 5 | 最后一页正好 5 条，`总页数 = 2` 而不是 3 |
| 总数 0 | 总页数应该是 1，不能是 0（否则页码区域是空的） |
| 筛选后只剩 1 条 | 页码夹回 1，表格正常显示 |

**`Math.ceil(0 / 5)` 等于 0** —— 这就是为什么代码里要写
`Math.max(1, Math.ceil(...))`。
:::
