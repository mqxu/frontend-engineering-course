1.3 学习路线与岗位方向 ​

先说一个共性问题 ​

学前端的人容易陷入一种状态：什么都看过，什么都做不出来。

今天刷到"Vue 3 组合式 API 真香"，学两天；明天听说"TypeScript 是刚需"，又去看两天； 后天看到"2026 前端已死"的帖子，心态崩了，躺一周。

问题不在于不努力，而在于不知道自己站在路线的哪个位置，所以每次都在重新开始。

解决这个问题只需要做一件事：把自己的位置标出来，然后只看下一站。

完整的路线在前端学习路线那一页，这一节聚焦两个更实际的问题： 我离过关还差什么，以及过关之后往哪走。

三阶段速览 ​

阶段目标关键词对应
一 · 打地基能用原生技术做出会动的页面HTML、CSS、JS、DOM、调试先修课程
二 · 上装备能用现代工程化方式做项目工具链、框架、组件、架构、交付本课程 48 学时
三 · 定方向能按岗位方向深入领域深度 + 工程能力后续课程与自学

判断自己在哪一阶段，用三个问题：

  1. 能不看资料写出一个带表单校验、能请求数据的页面吗？→ 过了第一阶段。
  2. 能在干净电脑上让你的项目 15 分钟内跑起来吗？→ 过了第二阶段的一半。
  3. 能说清你的项目为什么这么分层、这么拆组件吗？→ 过了第二阶段。

第二阶段的能力项自查 ​

这一阶段就是本课程的内容。下面这张表可以直接当自查表用，每一项的判断标准都是"能独立做出来"：

能力项过关标准对应单元自检题
工程化认知能说清工程化解决的六类问题1不看笔记说出那六类
工具链能独立初始化工程并配好规范2 - 3从空目录到跑起来，全程不查教程
框架核心会用组合式 API 写出响应式交互4 - 6手写一个带搜索、分页、排序的表格
组件化能按职责拆组件、设计接口7 - 8把一个 400 行的页面拆成合理结构
应用架构能用路由与状态组织多页面应用9 - 10实现强制刷新后登录态不丢
交付能力能打包、部署、写交接文档11 - 12别人按你的 README 能跑起来

自查时对自己诚实

最常见的自我误判是"这个我看过，算会"。看过的标准太低 —— 教程看一遍、视频刷一遍， 顶多算"知道有这个东西"。

真正的标准是：关掉所有资料，能不能从空文件开始写出来。 写不出来就如实打叉，回对应单元重做。诚实一点，反而省时间。

第三阶段的五个方向 ​

第二阶段结束后，你会面临选择。下面五个方向是当前就业市场上比较清晰的出口， 每个方向都写清了"日常做什么、要补什么、拿什么练手"。

方向一 · 业务开发 ​

最常见，岗位最多。

项目内容
日常做什么做后台管理系统、企业信息化系统、运营配置平台。大量表格、表单、权限、流程
核心技能复杂表单与表格、组件库二次封装、权限体系（菜单级 / 按钮级）、性能优化、TypeScript
要补什么TypeScript（重点）、Element Plus / Ant Design Vue 的深度使用、表单引擎
练手项目把本课程的校园活动平台加上"数据字典管理""操作日志""角色权限配置"三个模块
典型出口各类企业的前端团队、外包与项目制公司

为什么它岗位最多：因为绝大多数公司的前端工作就是"把内部流程搬到网页上"。 这个方向不需要炫技，需要的是稳、准、能处理边界情况。

方向二 · 跨端开发 ​

项目内容
日常做什么用一套代码出小程序、H5、App 三个端
核心技能uni-app 或 Taro、小程序规范、多端适配与条件编译、原生能力调用（支付、扫码、定位）
要补什么小程序的生命周期与分包机制、平台差异处理、真机调试
练手项目把本课程项目里的两个页面移植到 uni-app，跑通浏览器与小程序模拟器
典型出口小程序服务商、零售与本地生活类业务、外包公司

课程里的入口

单元 12 结束后给了一个课外拓展：用 uni-app 把“活动列表”与“活动报名详情” 两个页面移植到移动端，复用同一套接口。不占课内学时，是想走这个方向的同学的起点。

这个方向的坑：不要一上来就学"多端适配技巧"。先把一个端做扎实（比如小程序）， 再考虑多端 —— 否则三端都有问题，排查起来会崩溃。

方向三 · 服务端渲染 ​

项目内容
日常做什么做官网、内容型站点、电商前台这类需要被搜索引擎收录的页面
核心技能Nuxt（Vue 生态）或 Next.js、SSR 与预渲染、SEO 基础、部署到 Node 服务
要补什么HTTP 缓存、Node 服务部署、首屏性能指标（LCP、FCP）
练手项目用 Nuxt 做一个校园活动对外展示站，要求首屏内容在 HTML 源码里能看到
典型出口内容与电商类公司、需要 SEO 的业务团队

这个方向的门槛：它要求你同时对前端和后端部署有一定了解。 不像业务开发那样纯前端，但因此也更稀缺。

用一句话说清 SSR 解决什么问题

普通单页应用的 HTML 源码里只有一个空 <div id="app"></div>，搜索引擎抓到的就是"这个页面是空的"。 SSR 是在服务器上先把页面渲染成完整 HTML 再返回，搜索引擎和用户拿到的是有内容的页面。

代价是：多了一层 Node 服务，部署变复杂了，页面里有状态的代码要注意"在服务端能不能跑"。

方向四 · 质量与工程 ​

项目内容
日常做什么写测试、搭 CI 流水线、做监控与埋点、维护脚手架与构建配置
核心技能Vitest 单元测试、Playwright 端到端测试、CI 流水线、构建性能优化、监控体系
要补什么测试设计思路（测什么、不测什么）、Node 脚本编写、CI 平台（云效 Flow、GitHub Actions）
练手项目给本课程项目补上单元测试（从时段冲突检测这类纯函数入手）与一条自动构建流水线
典型出口前端基础设施团队、测试开发岗、中大型公司的工程效团队

这个方向最容易被忽略，但需求真实存在：团队越大，越需要有人负责"让大家写得顺"。

方向五 · 可视化 ​

项目内容
日常做什么做数据看板、大屏、地图可视化、图表交互
核心技能ECharts、Canvas 与 SVG、WebGL 基础、大屏适配、性能优化（大量数据点）
要补什么图形学基础、数据可视化设计原则、Canvas 图层与动画
练手项目给本课程的数据看板做一次升级：加一个可下钻的图表和一个地图分布图
典型出口数据可视化公司、BI 团队、政企大屏项目

这个方向的特点：入门容易（ECharts 会配就能出图），做深很难（数据量大时的性能、 自定义图形、交互设计）。

怎么选：三个判断依据 ​

不要靠"哪个听起来高级"来选。看这三条：

依据怎么判断
你做过什么还算顺手回顾过去半年，哪个任务你做的时候不觉得痛苦 —— 那就是信号
目标岗位的招聘要求打开招聘网站，搜你想去的岗位，看 20 条 JD 都提到什么，出现频率最高的就是必修项
你愿意为它花额外时间有些方向需要课外投入（比如可视化要学图形学）。想清楚你愿不愿意

一个更务实的建议

先选业务开发作为保底，再发展一个方向作为特色。

原因：业务开发岗位最多，容错率最高；而任何特色方向都需要一定的业务开发能力做基础 —— 可视化也得会写表格，跨端也得会做表单。

本课程的训练目标就是让你达到业务开发的入门水平，特色方向是加分项。

一份可执行的自学计划模板 ​

选好方向后，别写"我要学 TypeScript"，这没法执行也没有终点。用这个模板：

字段说明例子
目标具体到能做出什么用 TypeScript 重写本项目的 API 层与两个 store
交付物能拿出来看的东西一个提交记录，类型覆盖率达标
验收标准怎么算做完pnpm build 通过且无 any 类型
时间盒限定时间，避免无限拖延三周，每周 6 小时
卡住时找谁不要一个人硬扛先查官方文档，再问同学 / 老师

关键差别在于"交付物"和"验收标准"。 没有这两栏的计划，多半会变成"看了一堆教程，什么也没留下"。

小结 ​

  • 学前端最大的坑不是不努力，而是不知道自己站在哪。
  • 第二阶段的能力项自查表可以直接当清单用，标准是"能独立做出来"。
  • 五个方向：业务开发、跨端、服务端渲染、质量与工程、可视化。
  • 选方向的三个依据：做过什么顺手、招聘要求、愿不愿意多花时间。
  • 先保业务开发，再选一个特色方向。
  • 自学计划必须写清交付物与验收标准，否则等于没写。

常见坑 ​

坑 1：同时学三个方向

结果通常是三个都停在"入门教程看完"的水平。一个方向做到能讲清楚，比三个方向都听过一遍更值钱。

坑 2：把"换框架"当成"换方向"

从 Vue 换到 React，不叫换方向，叫换工具。方向是按解决的问题分的，不是按框架分的。 今天用 Vue 做后台管理，明天用 React 做后台管理，这是同一个方向。

坑 3：只是收集资料，不动手

存了 200 GB 的视频和电子书，一个项目都没做完。这类"学习"的产出是零。

检验方法很简单：把你过去三个月的学习成果列出来，有没有能演示的东西？ 没有就是有问题。

坑 4：看到"前端已死"就焦虑

每隔几年就会有一轮这样的说法。事实是：做简单页面的需求确实在减少， 但能做工程化交付的前端一直缺人。

这门课教的东西 —— 工程化、组件设计、异常处理、交付能力 —— 恰恰是 AI 工具最难替代的部分： 它们需要对项目的整体理解和取舍判断，不是生成一段代码能解决的。

课后练习 ​

练习 1：写出自己的位置与差距

用一页纸回答这四个问题：

  1. 我在三阶段的哪一站？
  2. 第二阶段自查表里，哪些我打了勾、哪些没打？列出具体没过的项。
  3. 这门课结束后，我想往哪个方向深入？给出两条理由。
  4. 这个方向目前我缺什么？

参考思路：第 2 问是关键。写"框架核心基本会了"没有意义，要写"计算属性会用， 但 watch 的 deep 和 immediate 说不清楚"，这样才知道下一步做什么。

练习 2：拆解 20 条招聘要求

到招聘网站搜索"前端开发工程师"，挑 20 条校招或初级岗位的 JD（不要挑高级岗位）， 把所有技能关键词统计出现次数，做成一张表。

参考思路：统计完你会发现几个规律 —— Vue / React 至少会一个、Git 是硬要求、 TypeScript 出现频率很高、有项目经验的要求几乎 100%。

这张表就是你后续学习优先级的依据：出现次数高的先学。

练习 3：写一份三周自学计划

按本节模板，给你选定的方向写一份三周计划。要求：必须有交付物和验收标准。

参考思路：计划要小到能做完。比如"三周学会 TypeScript"不行， "三周把项目的 API 层与两个 store 改成 TypeScript，pnpm build 通过，无 any"才行。
