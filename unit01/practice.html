单元 1 课后练习 ​

本单元的练习以"建立认知"为主，不写业务代码。四道必做题，两道选做题。

各小节末尾还有针对性的小练习，那些是帮助理解单点的；这一页的练习是单元级的产出， 会作为过程性考核的依据。

必做题 ​

练习 1 · 环境自检报告 ​

按 1.4 的模板写一份完整的环境自检报告。

提交形式：Markdown 文件，放在项目仓库的 docs/env-report.md。

验收标准

项目要求
版本信息Node、npm、pnpm、Git 四项齐全，含安装方式
自检清单7 项全部有明确勾选状态
问题记录至少一条，包含"现象 → 排查过程 → 原因 → 解决"四个环节
可复现性别人按你的报告操作，能装出同样的环境

不合格的写法

环境搭建完成，一切正常。

这句话什么信息都没有。报告的价值在于让别人能复现你的环境，以及记录你踩过的坑。

练习 2 · 个人学习路线图 ​

用一页纸说明你的当前位置与下一步。要求包含三部分：

  1. 当前位置：在三阶段路线的哪一站，判断依据是什么。
  2. 能力自查：第二阶段六项能力逐项判断，通过的写依据，没通过的写差距。
  3. 方向选择：选一个岗位方向，说明两条理由。

验收标准

项目要求
诚实没通过的项要如实列出，不允许全部打勾
具体差距要写成"某个具体用法说不清"，不能写"不太熟"
可执行方向选择要有理由，不能只写"因为感兴趣"
参考框架
md
## 一、当前位置

第二阶段开头。判断依据：能用原生 JS 做出带交互的页面，
但没独立配置过构建工具，package.json 里的字段有一半不认识。

## 二、能力自查

| 能力项 | 状态 | 依据 / 差距 |
| --- | --- | --- |
| 工程化认知 | 未通过 | 说不出工程化解决哪几类问题 |
| 工具链 | 未通过 | 只会 pnpm install，不会配 Vite |
| 框架核心 | 部分通过 | ref 会用，但 watch 的 deep 说不清 |

练习 3 · 现代前端工程结构分析 ​

到 GitHub 找一个人气较高的 Vue 3 项目，分析它的 src 目录结构，输出一份分析报告：

  1. 画出目录树（至少到第二层）。
  2. 标出下面各项的位置：页面组件、通用组件、接口定义、全局状态、工具函数。
  3. 找出这个项目里你认为命名最好的一处和最看不懂的一处，说明理由。

验收标准：报告要基于实际文件内容，不是只看目录名。比如判断 api/ 里放什么， 要打开其中一个文件确认。

推荐找什么样的项目

搜 vue3 admin 或 vue3 template，选 star 数 1k 以上的。避开两类极端： 太小的（只有一个页面，看不出结构）和太大的（几十个目录，看不懂）。

练习 4 · 自己的痛点清单 ​

回忆你做过的最大一个网页作品，按要求写一份痛点清单：

六类问题你遇到过的具体问题
模块化
依赖管理
编译转换
质量保障
自动化
协作交付

每类至少写一条。实在没遇到过的，写"为什么没遇到"（比如"一直是单人开发，所以没遇到合并冲突"）。

验收标准：至少有三条是具体的事件描述，而不是笼统的抱怨。

什么是"具体的事件"
  • ✗ 不好：代码很乱。
  • ✓ 可以：做到第三周时 app.js 涨到 900 行，找一个按钮的事件处理函数花了十几分钟， 最后发现它绑定在一个动态生成的元素上，用 on 委托绑的。

差别在于：后者能让你在学到对应单元时想起"对，我当时就是这个情况"。

选做题 ​

练习 5 · 报错日志 ​

做一个"报错日志"文件，坚持记录两周。格式不限，但每条要包含：

  • 报错原文（完整，不要只写"报错了"）
  • 你当时的操作
  • 排查过程（试过什么、排除了什么）
  • 最终原因
  • 一句话总结这类问题的排查入口

为什么值得做：这门课后面会遇到大量报错，而报错是工具在替你干活。 两周之后你回头看，会发现高频问题就那么几类。

练习 6 · 对比两个脚手架 ​

分别用 create-vue 和 create-vite 创建一个项目（都选 Vue 模板），对比：

  1. 目录结构的差异
  2. package.json 里依赖的差异
  3. 各自适合什么场景

参考思路：create-vue 是官方为 Vue 项目准备的，默认会问你要不要 Router、Pinia、ESLint； create-vite 是通用的，模板更"素"。理解这个差别，有助于你之后选脚手架时不盲目。

自检标准 ​

本单元的练习做完后，逐条自查：

  • [ ] 环境自检报告能让别人复现我的环境
  • [ ] 报告里的问题记录包含完整的排查过程，不只是结论
  • [ ] 学习路线图如实标注了未通过的能力项
  • [ ] 能说出工程化解决的六类问题
  • [ ] 能描述一个现代前端项目的标准结构，并解释每个目录的职责
  • [ ] 至少对一个真实项目做过结构分析
  • [ ] 痛点清单里至少有三条具体事件

全部打勾，这个单元过关。

常见问题 ​

我的电脑是 Windows，报告里的命令要改吗

要改。装 fnm 用 winget，环境变量那一步用 fnm env --use-on-cd | Out-String | Invoke-Expression 或者直接用 nvm-windows。报告里注明你用的是哪个工具即可 —— 不同平台的处理方式不同是正常的。

找不到合适的项目做结构分析怎么办

三个备选：

  1. 直接看本课程后面的单元 11 目录规划，对比自己的思路。
  2. 看 Vue 官方文档里推荐的项目结构说明。
  3. 找一个同学的课设项目，分析它的结构问题 —— 分析一个"不好"的结构同样有价值。
我完全没有前端基础，是不是该换个课

本单元不需要前端基础。但从单元 4 开始会用到 JavaScript 的数组方法、箭头函数、解构赋值、 Promise 这些内容。如果这些完全不熟，建议一边上这门课，一边补基础， 不然会在单元 5 开始跟不上。
