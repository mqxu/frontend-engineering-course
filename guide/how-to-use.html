怎么用这套教程 ​

这页说明教程的组织方式与阅读约定。花三分钟看完，后面能省不少时间。

每个单元的固定结构 ​

每个单元都是这套结构，位置固定，方便你快速定位：

text
单元导学          ← 目标、知识地图、这次课的产出
  ↓
知识点小节        ← 编号 1.1、1.2 …… 一节讲透一个问题
  ↓
案例 / 实战       ← 把本节知识点拼成一个能跑的东西
  ↓

“AI 协作”这一节不额外占课时，位置固定排在正文之后、练习之前。它讲的是这一章的 知识点怎么和 AI 配合、AI 在这里容易错什么、产出怎么验收。可以从 AI 编程：用之前先知道它的边界先看一遍总的方法。

用户端专栏的结构 ​

管理端之外的第二个端（uni-app 用户端）不按单元编号，它是一栏独立的 11 篇， 在顶部导航的“用户端”里。原因是这一端不占课时，属于管理端跑通之后的延伸， 硬塞进 12 周的结构里反而会把课时的节奏打乱。

篇内容
总览两个端一套后端、技术选型、两端版本差异的说明
1 - 2为什么是 uni-app、建工程跑起来
3 - 5页面与路由、布局与样式、组件与组件库
6 - 8请求封装与登录态、列表页与详情页、报名表单与我的报名
9 - 10打包与发布、AI 协作

每篇的结尾都有“上一节 / 下一节”的链接，顺着点就行。第 10 篇的 AI 协作单独讲跨端代码 最容易想当然的地方（比如组件库换了包名、用了浏览器 API），和管理端那 12 节是同一套思路。

import { ref, computed } from 'vue'

const count = ref(0)

  count.value += delta
}
</script>

  <button @click="step(1)">+1</button>
  <button @click="step(-1)">-1</button>
</template>

排版与术语约定 ​

统一约定是为了减少歧义：

写法含义
单元 4第 4 周上课的那个单元，一次课讲完
第 4 章旧版教程的章节，仅在对照旧资料时出现
./src/views/以项目根目录为起点的相对路径
菜单 → 设置从“菜单”进入“设置”，依次点击
Ctrl + S快捷键，macOS 上对应 Cmd + S

代码里的版本号都是核对过的。 文中的依赖版本按 npm 仓库现状核对，教学统一用稳定版，不追预发布版本。 完整清单见工具链与版本清单。

关于示例代码 ​

教程里的代码都能跑，但不是每段都要照着抄。三类代码要区别对待：

类型怎么处理
完整文件（带文件名的代码块）直接抄进项目，按注释改
片段（只贴关键几行）看懂了就行，不用抄
错误示范（标了"✗"）不要抄，这是用来对比的反例

抄代码的正确姿势

抄一遍 → 改几个地方 → 看变化 → 说清为什么变化。四步走完，才算学会。 只抄不改，等于把代码从教程搬到编辑器，技能没有发生转移。

课后练习怎么算做完 ​

每章练习末尾都有自检标准，标准统一是能独立做出来：

  • [ ] 能不看教程写出主要代码
  • [ ] 能说清为什么这么写，而不是"教程上就是这么写的"
  • [ ] 遇到报错能自己定位，不靠问人

三条都打勾，这个单元就算过关。做不到就回看对应小节 —— 教程里每个坑都有说明， 如果还是卡住，多半是前面的某个前置知识没掌握。

建议的阅读顺序 ​

如果时间充裕，按顺序读 12 个单元。如果时间紧张：

  1. 只想尽快写出页面：单元 4 → 5 → 6 → 7，跳过工具链，边写边补。
  2. 只想弄懂工程化配置：单元 1 → 2 → 3，配合单元 12 的构建与部署。
  3. 要交项目了：直接看综合项目和各案例，缺什么补什么。
  4. 还要做手机端：先把管理端的登录与请求层做完，再进用户端专栏按顺序读。

不过说实话，最省时间的路径还是按顺序读 —— 后面的内容默认你掌握了前面的东西， 跳跃阅读容易在某个小地方卡住，反而更费时间。
