课程导读 ​

一句话定位

这门课不教你写第一个网页，而是教你把一个能跑的网页，变成一个能交付、能协作、能维护的工程。

这门课解决什么问题 ​

先看几个几乎每个前端新手都会遇到的场面。

  • 代码写完能跑，但换台电脑就报错，因为"我记得装过某个包"。
  • 三个人一起写，合并代码时冲突一堆，谁都不敢动别人的文件。
  • 页面上线后用户反馈白屏，本地怎么试都是好的。
  • 需求改一次，同样的逻辑要在五个文件里各改一遍。
  • 接口一慢，页面就卡在那里转圈，用户不知道发生了什么。

这些问题的共同点是：它们都不是"语法不会"造成的。语法可以查文档，而上面这些是工程问题 —— 属于 怎么组织代码、怎么管理依赖、怎么保证质量、怎么协作交付的范畴。

前端工程化要做的，就是把这些靠"经验"和"小心"来避免的麻烦，变成有工具、有流程、有约定的常规动作。

学完这门课，你应该能够 ​

知识层面

  • 说清前端工程化要解决的六类问题：模块化、依赖管理、编译转换、质量保障、自动化、协作交付。
  • 说清一个现代前端项目的目录结构、配置文件、脚本命令各自在做什么。
  • 说清 Vue 的响应式是怎么知道"数据变了"的，以及为什么有些写法会失去响应性。
  • 说清单页应用的路由、状态管理、请求层三者之间的职责边界。

能力层面

  • 在一台干净机器上，从零搭出一个带检查、格式化、提交钩子的前端工程。
  • 独立完成一个完整的业务页面：列表、表单、状态流转、加载与错误处理。
  • 用 Vue 3 组合式 API 拆组件、抽组合式函数、写自定义指令。
  • 用路由守卫与状态管理实现一套完整的登录鉴权。
  • 把项目打包、部署到服务器，并写出让别人能跑起来的说明文档。
  • （延伸）用 uni-app 把同一套后端接口接到手机端，一套代码编译到 H5 与微信小程序。

素养层面

  • 养成"先想清楚再写"的习惯：需求 → 页面清单 → 接口清单 → 代码。
  • 对异常状态有敏感度：宁可多写一个错误提示，也不让用户对着白屏猜。
  • 会用工具查问题，而不是靠反复试。

学时分配 ​

总共 48 学时，按 12 周 × 4 学时安排，每周一个单元，一个单元正好一次课。

模块主题学时周次
一工程化认知与工具链12第 1 - 3 周
二Vue 3 核心基础12第 4 - 6 周
三组件化开发8第 7 - 8 周
四应用架构8第 9 - 10 周
五综合项目实战8第 11 - 12 周

理论讲讲授与实践的比例大致是 1 : 2。工具链占了 12 学时，是因为这部分恰恰是学生最缺、 遇到问题时最耗时间的环节 —— 前置讲透，后面 36 学时的写代码效率会明显提高。

一次课是怎么过的 ​

每次课 4 学时，按下面的节奏推进：

环节时长做什么
检查预习0.3 学时现场抽问本单元的知识点，确认示例都跑过
讲解1.3 学时只讲重点与容易踩的坑，不逐行念代码
现场任务1.8 学时做本单元的实训任务，老师在教室里走动排错
复盘0.6 学时展示两三个同学的写法，对比不同解法的取舍

课内时间不够讲完所有细节，所以每个单元都标注了配套章节，要求课前通读并跑通示例。 课后作业以"改造 + 排错"为主，不布置照抄题。

考核方式 ​

类别占比评分项
过程性40%课堂实训任务完成度（20%）、课后案例作业（15%）、出勤与课堂参与（5%）
阶段性20%工程模板验收（第 3 周，10%）、路由与状态综合任务（第 10 周，10%）
终结性40%综合项目源码与功能（15%）、部署与演示（10%）、答辩与文档（15%）

所有评分项都有可留存的证据：代码仓库、提交记录、部署地址、评审记录。没有闭卷记忆类考核。

综合项目 ​

项目是校园活动服务平台，取“活动发布 → 报名审核 → 场次安排”这条主线。它有两个端：

端做什么技术是否占用课时
管理端组织者发布活动、审核员审批报名、排场次与场地Vue 3 + Vite + Element Plus是，贯穿 12 个单元
用户端学生用手机看活动、报名、查报名记录uni-app + Wot UI否，独立专栏，课后延伸

管理端规模控制在 12 周内能完成的范围；用户端是管理端跑通之后的第二个端，5 个页面， 共用一套后端接口。两端的详细规格都在项目文档里。

项目从第 3 周建仓库就开始，之后每周的课堂练习都在同一个工程里做，第 11 - 12 周只做收口。 这样安排的原因很实际：课内留给项目的时间只有 8 学时，如果等到第 11 周才动手，一定做不完。

你需要准备什么 ​

基础：会写 HTML 结构、能用 CSS 做基本布局、看得懂 JavaScript 的函数与数组方法。 如果这几项不熟，建议先补前面那门课 —— 这门课不会停下来讲 const 和 for 循环。

机器：一台能装 Node.js 的电脑，8 GB 内存以上。不需要独立显卡。

心态：这门课会遇到大量报错。报错不是失败，是工具在替你干活。学会读报错，比记住语法更重要。

三个学习建议 ​

关于"抄代码"

抄代码本身没问题，问题是抄完不看结果。教程里的每一段代码都能跑， 建议抄一遍 → 改几个地方 → 看变化。改完之后还能解释为什么变化，才算真会了。

一、把每一章的示例都在自己的工程里跑一遍

只看不写，等于没学。工程化的知识，一半在配置文件的细节里，另一半在报错的解决过程里。

二、遇到问题先看报错的最后一行

绝大多数报错信息已经写清了原因和位置。教程的常见报错与排查整理了高频问题， 但更重要的是养成"从报错里找线索"的习惯。

三、给每个单元留一份产出

每个单元都有明确的课堂产出（配置模板、状态模块、业务页面）。这些产出不是应付检查的， 它们会直接成为综合项目的一部分。认真做，项目阶段能省一半力气。
