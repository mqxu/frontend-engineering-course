必做题 ​

练习 1 · 个人名片页（含交互） ​

这是本单元的核心产出。做一个“校园活动服务平台”的个人名片页， 展示当前登录用户的信息，并且带交互。

功能要求

项目要求
头像用 :src 绑定图片地址，地址来自状态，不要写死在标签里
姓名用插值表达式展示
角色标签三种角色：活动组织者（organizer）、审核员（auditor）、学生（student），不同角色不同颜色，用对象形式的类名绑定实现
在岗 / 请假状态点击按钮切换；切换后标签的文字和颜色都要变
主题色切换提供至少三个候选颜色，点击后整张卡片的强调色跟着变；颜色值放在状态里，通过 CSS 变量传递
技能标签列表用 v-for 渲染一个字符串数组

技术要求

  1. 所有会变的数据都用 ref 或 reactive 声明；
  2. 不允许出现 document.querySelector、innerHTML、classList；
  3. 数据可以先用本地写死的对象，不需要接口。

提交形式：src/views/ProfileCard.vue（或你项目里对应的路径）， 外加一份 100 字左右的说明，讲清楚你把哪些东西变成了状态。

参考结构（先自己写，卡住了再看）
vue
<script setup>
import { ref } from 'vue'

const user = ref({
  name: '林一鸣',
  avatar: 'https://cdn.example.com/avatar/lin.jpg',
  role: 'organizer'
})

const isOnDuty = ref(true)
const themeColor = ref('#2f6fed')
const skills = ref(['需求梳理', '活动执行', '数据复盘'])

const ROLE_TEXT = {
  organizer: '活动组织者',
  auditor: '审核员',
  student: '学生'
}
</script>

<template>
  <section class="profile-card" :style="{ '--theme-color': themeColor }">
    <img class="profile-card__avatar" :src="user.avatar" :alt="user.name" />
    <h2 class="profile-card__name">{{ user.name }}</h2>

    <span
      class="role-tag"
      :class="{
        'role-tag--organizer': user.role === 'organizer',
        'role-tag--auditor': user.role === 'auditor',
        'role-tag--student': user.role === 'student'
      }"
    >
      {{ ROLE_TEXT[user.role] ?? '未知' }}
    </span>

    <span class="duty-tag" :class="{ 'duty-tag--off': !isOnDuty }">
      {{ isOnDuty ? '在岗' : '请假' }}
    </span>

    <ul class="skill-list">
      <li v-for="skill in skills" :key="skill">{{ skill }}</li>
    </ul>

    <div class="profile-card__actions">
      <button @click="isOnDuty = !isOnDuty">切换在岗状态</button>
      <button @click="themeColor = '#2f6fed'">蓝色主题</button>
      <button @click="themeColor = '#0f9d58'">绿色主题</button>
      <button @click="themeColor = '#e8710a'">橙色主题</button>
    </div>
  </section>
</template>

<style scoped>
.profile-card__name {
  color: var(--theme-color, #2f6fed);
}

/* 其余样式略 */
</style>

注意：参考结构只是为了说明“把哪些东西变成状态”。 样式、布局、交互细节请自己设计，不要照抄。照抄的话这个练习就白做了。

验收标准

项目要求
数据驱动页面上所有会变的地方都来自状态，改状态界面就变
没有 DOM 操作全文搜索 querySelector、classList、innerHTML 均为零
类名绑定角色标签用对象形式，不是 v-if 链
主题色通过 CSS 变量实现，不是给每个元素单独算样式
可运行pnpm dev 打开页面无报错、无警告

最常见的三类不合格

  1. 角色标签用了 v-if 链。 题目要求用对象形式的类名绑定， 目的是让你练“类名跟着状态走”这个思路。
  2. 主题色是给每个元素写 :style。 这样加一个用到主题色的元素就要改一处模板。 正确做法是外层定义 CSS 变量，内部样式引用变量。
  3. 切换在岗状态时去改 classList。 这是命令式写法，说明思路还没转过来。

练习 2 · 命令式与声明式各写一遍 ​

同一个需求，写两版，量一量差距。

需求：渲染一个活动报名记录列表，每条显示“学生姓名 + 学号 + 审核状态”， 点一下在“待审核 / 已通过”之间切换，底部显示“已通过 N 人 / 共 M 人”。

版本 A：原生 JavaScript。要求只用 DOM API，不用任何框架。 必须包含：手动渲染列表、点击时 findIndex 找到对应记录、改完之后手动重新渲染。

版本 B：Vue。用 <script setup> + 模板实现。

要交付的内容

项目要求
两个版本各自一个可运行文件
行数统计分别统计总行数（不含空行与注释）
对比表按下面四条逐项对比

对比表要填这四项：

对比项版本 A版本 B
谁负责找元素
谁负责把数据搬到界面
同一个事实存了几份
加一个“只显示待审核”的开关，要改哪里

验收标准：最后一栏是重点。要具体写出“A 版本改了哪几处、B 版本改了哪几处”， 不能只写“A 改得多”。

参考思路
  • 版本 A 加筛选开关，至少要改三处：render() 里的循环条件、 点击处理里“切换后该项可能要从列表消失”、以及筛选按钮自身的高亮状态。
  • 版本 B 通常只改一处：把 v-for 的数据源从一个数组换成一个筛选后的结果。
  • 如果你在版本 B 里也想不出“怎么只改一处”，说明还没理解声明式的思路， 回头再看一遍 4.1。

练习 3 · 活动状态标签组件 ​

实现项目里的 ActivityStatusTag 组件。

功能要求

状态值显示文字颜色（自行选择合适色系）
draft草稿灰
signing报名中绿
closed报名截止橙
finished已结束蓝

技术要求

  1. 必须用对象形式的类名绑定（这是本题的核心考点）；
  2. 文字用映射表算出来，不要写 v-if 链条；
  3. 支持一个 size 属性，取值 small / default，用数组形式叠加类名；
  4. 传入非法的 status 时，控制台要有警告（提示：defineProps 的 validator）；
  5. 非法状态渲染成“未知”，不能白屏或报错。

提交形式：src/components/ActivityStatusTag.vue。

验收标准

项目要求
类名绑定用对象形式写四个状态的判断
尺寸size 用数组形式叠加，默认值是 default
容错传非法状态不报错，显示“未知”并给出警告
复用在同一页面里连续放四个标签，四种颜色都正确
提示：为什么这题要求用对象形式

因为后面组件化开发时，父组件传什么状态是运行时才知道的。 对象形式让你能一眼看出“哪几个类名、各自在什么条件下生效”， 也方便以后加第五种状态 —— 加一行对象属性即可。

字符串形态（'tag--' + status）虽然更短，但在“条件和类名不是一一对应”时就不够用了。 两种形态都要会，按场景选。

选做题 ​

练习 4 · 造一个 bug 再修好它 ​

这道题分两步，第一步是“故意写错”。

第一步：写一段代码，满足下面所有条件，让“改了数据但界面不动”真的发生。

要求：使用 reactive 声明一个活动对象；在某个函数里改它的属性； 页面渲染这个属性；但界面不更新。

第二步：写一段说明，包含四部分：

部分要写什么
现象点了什么、期待看到什么、实际看到什么
排查你按什么顺序查的（对照 4.4 的三步排查）
原因从“读取 / 写入 / 拦截”的角度解释为什么会这样
修法怎么改，改完之后为什么就对了
三个可选的错误方向

选一个造，或者三个都试：

  1. 解构丢响应性：const { title } = form，然后改 title；
  2. 整体替换 reactive 对象：form = { title: '...' }；
  3. 忘了 .value：const form = ref({...}) 之后写 form.title = '...'。

提示：第 2 种在 const 声明下会直接报错，要改成 let 才能“成功地写错”。 报错本身也是一种排查线索 —— 想想为什么报错反而比不报错容易定位。

为什么值得做：能造出这个 bug，说明你已经理解了机制；能解释它，说明你能排查它。 以后在项目里遇到同类问题，你会有明确的排查入口，而不是靠猜。

自检标准 ​

做完这个单元，逐条自查：

  • [ ] 个人名片页里没有任何 DOM 查询与类名操作
  • [ ] 角色标签用的是对象形式的类名绑定
  • [ ] 主题色通过 CSS 变量实现，改一个状态能影响多处样式
  • [ ] 命令式和声明式两版都能跑，对比表四项都填了具体内容
  • [ ] 状态标签组件四种颜色正确，非法状态有警告且不报错
  • [ ] 能不看资料说出“模板里能放什么、不能放什么”
  • [ ] 能说清 ref 与 reactive 各自的三个使用限制
  • [ ] 能用“读取时收集、写入时通知”解释响应式原理
  • [ ] 遇到“改了数据界面不动”，知道按哪三步排查

全部打勾，这个单元过关。

常见问题 ​

头像图片加载不出来怎么办

先按顺序查三件事：

  1. 地址对不对：在浏览器里直接打开那个 URL，能显示就说明是代码问题；
  2. 有没有写 :src：写成 src="user.avatar" 的话，浏览器会去请求一个 名叫 user.avatar 的文件，必然是 404；
  3. 是不是跨域或防盗链：随便找一个网图可能会被对方站点拒绝。 本地开发建议把图片放进 src/assets/，用 import 引入。

如果只是想练代码，用一个纯色 SVG 占位符也完全可以，不要把时间花在找图上。

主题色用 CSS 变量之后，样式检查工具报错

Stylelint 可能会提示 var(--theme-color) 里的自定义属性没有定义。 这是正常的 —— 因为它是运行时通过 :style 注入的，静态检查看不到。

两种处理：一是把变量名加进 Stylelint 的白名单配置； 二是在组件的 <style> 里给一个默认值兜底， 比如 color: var(--theme-color, #2f6fed)。推荐第二种，它同时解决了 “没传颜色时不显示”的问题。

练习 2 里，两个版本行数差距没到“十几行”怎么办

差距多少不重要，重要的是对比表里那四项。

如果你的原生版本写得特别短，通常是因为用了模板字符串一次性拼 HTML （innerHTML = list.map(...).join('')），再接一个事件委托。 这确实更短，但代价是：每次状态变化都要重建整段 HTML， 而且事件要重新委托。 加一个筛选开关、加一个行内编辑， 代码量会迅速涨上去。

可以试着真加一个筛选开关，然后再统计行数。这个实验做完， 你会对两种写法的差距有更真实的认识。
