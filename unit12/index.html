联调优化部署与答辩

模块五 · 综合项目实战4 学时第 12 周
学完这个单元，你应该能够
  • 能用 Postman 或 Apifox 独立排查接口问题，说清是前端传错了还是后端返回错了
  • 能读懂构建产物报告，并动手把首屏体积降下来
  • 能把前端项目打包并部署到一台服务器上，用真实域名访问
  • 能写出结构完整、数据可验证的交付文档，并完成一次 10 分钟答辩
课堂产出
联调问题记录表构建优化前后对比数据线上可访问的地址项目交付文档与答辩 PPT

最后一次课，要做的是“交出去” ​

前面十一周，你写的是代码。这一周要做的是把代码变成别人能用的东西。

这两件事的距离比想象中大。学生的常见情况是：本地跑得好好的，一打包就白屏；或者部署上去了，刷新页面 404；或者交上去的文档只有一句“实现了活动管理功能”。

这个单元的四个小节，正好对应交付前的四道关：

关卡会出现的问题在哪一节讲
前后端对接接口通了但字段对不上、跨域、token 失效12.1
打包产物 3 MB、首屏白屏 5 秒12.2
部署刷新 404、接口 404、资源加载失败12.3
交付文档说不清楚、答辩讲不到重点12.4

四道关的顺序不能换。 先把功能调通，再考虑快不快；先能跑起来，再考虑放在哪跑；先自己确认好，再去讲给别人听。

本单元的知识地图 ​

小节讲什么解决什么问题
12.1 前后端联调联调流程、字段核对、跨域、token 与 401、常见 4xx 排查接口报错时能定位是谁的问题
12.2 构建优化产物分析、路由懒加载、按需引入、分包、图片处理首屏体积从几 MB 降到几百 KB
12.3 部署上线打包、Nginx 配置、history 模式回退、环境变量、域名与 HTTPS得到一个能给别人访问的地址
12.4 交付材料与答辩交付文档结构、README 写法、答辩 PPT 与讲稿、常见提问把做过的事讲清楚
AI 协作 · 优化建议要先验证部署配置的常见漏项、优化建议的测量方法、交付材料核对没有测量就没有优化

这次课的 4 学时怎么用 ​

环节时长做什么
联调实操1.2 学时把前端接到真实（或同学写的）后端上，跑通登录 → 活动列表 → 新增活动这条链路
优化实操1.0 学时跑一次 build，看产物报告，做两三项优化，记录前后数据
部署实操1.0 学时打包、部署到服务器或静态托管平台，确认线上可访问
答辩与讲评0.8 学时每人 3 分钟讲核心思路与一个技术难点，同学互评

这次课最容易崩的地方

一、等到最后一次课才开始联调。 单元 11 结束时，你应该已经用 mock 数据把功能做完了。如果你的后端同学也拖到今天才写完第一版接口，那这次课一定完不成 —— 两边都有 bug 的时候，排查时间会翻好几倍。

建议：单元 11 下课后就和后端同学约一次，先对字段，再接最简单的那个接口。

二、优化和部署没时间做。 有些同学把时间全花在补功能上，最后只是本地截了张图交差。“部署上线”是这门课的硬性要求，线上地址和本地截图的分量完全不同 —— 前者任何人都能打开，后者只能证明你的电脑上跑过。

这个单元的产出 ​

一、联调问题记录表

联调过程中一定会遇到问题。把每一个记下来：

编号现象排查过程定位处理
1登录后跳转正常，但刷新就退回登录页看 Application → Local Storage，token 在；看 Network，刷新后请求没带 token请求拦截器在应用初始化前就创建了，拿不到 store 里的 token拦截器里改成调用时才取 token

这张表比“功能都实现了”这句话有价值得多。 它证明你真的调通过，而不是抄了别人的代码。

二、构建优化前后对比数据

至少包含三项：

指标优化前优化后
产物体积（dist 总大小）
最大的单个 JS 文件
首屏 JS 体积（初始加载的 chunk 之和）

数据要真实。 跑两次 build，把终端输出和 dist 目录的大小截图留着。

三、线上可访问的地址

要求：

  • 用真实浏览器打开能正常登录、能看列表、能新增
  • 直接刷新任何一个子路由（比如 /activity）不 404
  • 地址不是 localhost，也不是只能在你自己电脑上访问的地址

四、项目交付文档与答辩 PPT

交付文档至少包含：项目简介、技术栈、功能清单、如何本地运行、如何部署、已知问题。

答辩 PPT 5 到 8 页，10 分钟讲完，重点讲一个技术难点是怎么解决的。

具体的写法见 12.4 交付材料与答辩。

开始之前 ​

  • 功能已经做完了。 这个单元不写新功能，只做联调、优化、部署、交付。如果活动管理模块还没跑通，先回去补完单元 11 的必做题。
  • 有一台能部署的机器。 系里给的服务器、云厂商的学生服务器、或者静态托管平台（Vercel / Netlify / Cloudflare Pages 都可以）。
  • Git 仓库是干净的。 部署时从仓库拉代码，本地有未提交的改动会漏文件。

读完之后 ​

单元 12 是这门课的最后一站。做完之后你会有一个能被别人访问的线上项目和一份说得清来龙去脉的文档 —— 这两样东西放在简历里，比“熟悉 Vue 3”这几个字有说服力得多。
